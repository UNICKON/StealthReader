# StealthReader

![version](https://img.shields.io/badge/version-1.1.0-blue)
![platform](https://img.shields.io/badge/platform-Windows%2010%20%2F%2011-lightgrey)

StealthReader 是一个 Windows 桌面阅读器。窗口呈无边框、置顶、半透明的浮层，不占任务栏，正文区域是一个只读文本视图。同一窗口可以承载三类内容：本地书籍、社区帖子与 Anki 卡片，它们共用同一套渲染与显示控制。

## 功能

### 阅读

- 支持 TXT 与 EPUB。EPUB 的目录同时解析 OPF manifest 与 NCX/nav 两种来源；TXT 自动识别 UTF-8 与 GBK 编码，并按标题行划分章节。
- EPUB 正文按 HTML 语义抽取：`<p>`/`<div>` 这类块**里面**的源码换行只是空白，只有 `<br/>` 和块边界才断行；源码换行在中文之间带出来的空格会去掉。所以脚注标记（`<sup>①</sup>`）留在原句里，不会每一个都单独成行——这本书（《庄子今注今译》，CRLF 的 XHTML）修前是 20198 行、7202 个标记各占一行，修后 8876 行。
- 注释能点：EPUB 里 `<a href="#…">` 这类内部链接会被解析成"字符偏移 ↔ 字符偏移"的跳转表，正文里点 ① 这种标记就跳到注释那一条，再点注释里的 ① 跳回原文（《庄子今注今译》这本书解析出 7282 个可点位置、1841 组互跳）。书里只给了"去"的链接时，两边都是标记符就自动补一条回来的，不然点进注释就出不来。偏移按洗行后的列号精确到那个字——只记行首的话，段中间的标记会跳到段首。TXT 没有链接，自然没有这个行为。
- 分页依据实际渲染结果计算：每次载入一段文字，下一页的起点由当前视口内的实测位置决定；改变字号、行距或窗口尺寸后，阅读位置不会错乱。
- 阅读进度以全书字符偏移保存，重新打开或调整排版后仍回到原处；**而且按书各记一份**（`config.json` 的 `local_book_positions`：规范化绝对路径 → 字符偏移，只留最近 60 本）。换一本书再切回来，仍落在原来那一行；以前只有一个坑位，换书会把上一本的位置写成 0。
- 可设置字体、字号、行距、段间距、页边距与首行缩进。**字号单位是像素（px）**，书页和社区页同一套单位（设置里两个字号框都标着 `px`）；2026-11-10 之前书页字号写的是磅，老配置首次启动会按 13pt→17px、14pt→19px 自动换一次，视觉大小不变。
- 选中文字可添加五色高亮与笔记；可为当前页添加书签；目录、书签、划线集中在一个面板中查看与跳转，并可导出为 Markdown——导出口在**本地书架底部「📤 导出笔记」**：选中哪本就导哪本（按章分组，`本书名.划线笔记.md` 落在书旁边，那本书不用先打开）。
- 社区页正文有三套现成的排版方案（设置 → 社区 → 排版方案），随时切：
  **灵犀**（正文 16px / 行高 1.625 / 段间距 8px / 标题 24·21·18 / 代码 13px / MiSans 优先 → 雅黑）、**DSH Desktop**（14px / 1.714 / 16px / 21·19·18 / 11px / 纯系统字体栈）、**经典**（15px / 175%，标题只比正文大 1px）。只有帖子正文块跟着方案走，列表和评论仍是紧凑阶梯；单独调过字号就按正文比例整体联动（20px 时灵犀的标题 30、代码 16、段间距 10）。本机没装 MiSans 就落到雅黑。想要真的像灵犀，把 MiSans 的 .ttf 丢进程序目录的 `fonts/`，重启即生效（私有加载，不装进系统，看得到日志「自带字体已加载：…」）。另外：设置里勾了「社区页用单独字体」的话，那个字体和字号会**盖掉**方案里的字体栈。

**阅读页（书页正文、卡片、页脚）也认 `fonts/` 里的字**：`QFont("MiSans")` 在没装的机器上
不报错，Qt 会直接把它替成宋体（实测同一行 17px：请求 MiSans → 暗像素 1244/墨量 251235，
雅黑 2315/410454，宋体 1499/314790），所以书页字体一律先过 `resolve_font_family()`：
真有就用，没有就按 MiSans → 微软雅黑 的顺序往下落，并往日志写一行「字体 X 没有，实际用 Y」。
把 MiSans 的 ttf 放进 `fonts/` 后重启，书页就真是 MiSans（同一行实测暗像素 2660/墨量 481950，
比雅黑粗、和宋体明显不同）。MiSans 版权属小米，按其许可协议仅在本机使用、不再分发，
所以 `fonts/*.ttf` 不进仓库。
- 本地书架：读过的书 + 程序目录里 `books/` 下放着的 txt/epub/md，一列排开、各记各的进度，双击接着读。
- 阅读统计（入口是书页**右键菜单**里的「📊 阅读统计」；书架底部那个位置换成了导出笔记）：**开着一本书**点进去先看那本，没开书就是全部书籍；书架里没选书点进去同样是全部。
  右上角一个**窗口开关**：今天 / 本周 / 本月 / 全部（每次打开停在「**本周**」——今天常常只有十几二十分钟，看不出趋势；这个选择不写进 config）。
  整页跟着它变，不是只换个数字：
  - **六块卡**都只算这个窗口——时长 / 字数 / 速度 / 场次 / 最好的一天 / 连续阅读；时长卡下面还带一行
    「对比上期 ↑ 23%」（今天比昨天、本周比上周、本月比上月，「全部」没有上期就不给）。
    连续天数是跨窗口的全局数，卡里写明了；单本书页里的「进度」也是这本书的总进度，不随窗口变。
  - **粒度自动**，不用人挑：今天 = 00:00–24:00 的 5 分钟一格活跃带（颜色深浅 = 那一格读了多少）；
    本周 / 本月 = 一天一根柱；全部 = 跨度超过两个月就一个月一根柱。图标题直接写当前用的是哪种
    （「本周 · 按天」「全部 · 按月」）。柱子悬停给「11-08 · 1 小时 12 分」。
  - **会话表**按天分组：每组先一行小标题「11-10 周一 · 2 场 · 合计 1 小时 12 分」，下面才是每场的
    活跃条 / 开始 / 时长 / 字数 / 速度 / 书名；换窗口就只剩这个窗口里的那几天。
  - **书籍榜**同样跟窗口：书名 / 占比（横条 + 百分比）/ 本窗口时长 / 字数 / 速度 / 在读天数 / 累计。
    累计是这本书的总账，不随窗口走，好让你看清"这周只读了 20 分钟，但累计已经 6 小时"。
  - **热力图**永远是近 53 周（一列一周、一行一个周几，颜色 = 那天读了多久，鼠标停格看时长），
    所以切到热力图那一页，窗口开关会自己藏起来。
  **时序活跃图**三处：会话表每行左边一条迷你条（绿 = 在读、灰空 = 歇着，一眼看出这场歇过几回）；
  选中一场，下面展开这一场的分钟级时间线（整点刻度、空隙标「歇 18 分」、悬停看那一刻在读还是歇着）；
  概览里今天那一档本来就是这条带（00:00–24:00，5 分钟一格）。
  会话的**开始时间悬停**给详情：开始 / 结束（到秒）、跨度、在读（含"中间歇了 25 分，共 2 次，最长 18 分"）、
  字数与速度、书名；表里其它格子悬停给同一条。
  时间线的两头直接写**开始 / 结束**的具体时间（不只是中间那几个整点刻度）；条的终点 = **最后一次在读**：收场前那段沉默（同一本书要断满 15 分钟才算另一场）不画进场内，所以条子右端不会留一条没来由的灰尾巴，绿段加起来正好等于账上记的在读时长（那段沉默在悬停里写明「收场前静了 X 分（不算场内）」，不闷掉）。
  计时口径：窗口露着 + 正文是书才开始，**5 秒一拍**；3 分钟没有任何输入（翻页 / 滚轮 / 开书）就**停止计时**，
  但这一场先不收——盯着一页想事情不算离开。要等**同一本书断到 15 分钟**才算这场结束；断不到 15 分钟再回来
  接着读（切窗口、锁屏、翻别的书查一句、甚至退出重开）都**并回同一场**，中间那段不读的时间记成场内的
  `gaps`。所以一场可以很长（一两个小时很正常）、中间带几段灰，会话表里一场就是一场，不会碎成一串。
  接不上上一场、本身又读了不到 1 分钟的整段不记（打开又关掉、随手瞄一眼那种不占一条会话）。
  旧口径留下来的碎场（一场只有几秒、几十秒）不用删，直接并成这个口径就行：`reading_stats.consolidate()` 只重排会话表，**秒数、字数一分不改**——同书断不到 15 分钟的并成一场，老记录没记的场内空隙补成 `gaps`（不然时间线上画的“在读”会比账上记的时长多出一截）；日账 / 书账按并完的场次重算（`n` 是场次，所以会跟着变小）。对同一份账本反复调用结果稳定，不会越并越多空隙。
  所以挂着窗口去开会不算时长；代价是长时间盯着一页不动也会少记——宁可少记，不虚报。
  一场读久了每分钟落一次盘（写进账本再接着开，下次合并回同一场），被强杀最多丢一分钟。
  字数只累加**正增量**，往回翻不扣；跨零点的通宵算在开始那一天。账本单独放 `reading_stats.json`，
  **不进 `config.json`**（那个每次保存整体重写，日账塞进去早晚被冲掉）。

- 窗口层级：**统计页、本地书架、目录/书签/划线、设置**这四个窗口和页内右键菜单一样都带 `WindowStaysOnTopHint`。正文页是常驻顶层（`Qt.Tool | WindowStaysOnTopHint`），子窗口不顶层就只会待在普通层，正文页一铺过来就把它盖住——量过：正文页 `WS_EX_TOPMOST=True`、统计页 `False`、Z 序还排在正文页后面，所以以前点开统计只看得见露在书页外面的那一圈。

### 社区

各站点被统一为帖子、评论与内容块三种结构，因此不同来源的浏览方式和排版保持一致。

支持的来源包括 IT之家、知乎、微博、NGA、小红书、虎扑、豆瓣、linux.do、V2EX、GitHub 趋势与 Medium，以及自定义 RSS/Atom 订阅。

- 列表、正文与评论树在同一窗口内呈现；评论可逐条折叠，层级以缩进表示。
- 从列表点进帖子再退出（`Backspace`、`Esc`、`Z` 三条路都算），回到的正是**点进去时那一行**，
  不是列表顶上：进帖那一刻先把滚动位置记下来，退出时按它回位，再把人读到的那条 ensure 进可见区。
- 折起分两档：`X` 只收当前这一楼的回复（评论本身照读），`Shift+X` 整页只看主楼；
  再按一次摊回折之前的条数。点子评论也是折它所在的整楼——第几层都一样。
- 折起来之后屏幕停在**这条评论的底部**（不是它的开头）：长评论读到一半收起时，
  人留在自己刚读到的尾巴上；底部本来就在屏幕里就一动不动。
- 单条**收起**（点它任意一行）时，表头还在屏幕上就一动不动；表头已经滚出屏幕上方
  （知乎热榜那种好几屏的长回答，点在正文里收起它）就落到**这条回答自己的顶部**——
  不然"留在原地"早就不在屏幕上了，人会莫名被甩到它后面的内容上。
- 评论分批摆：顶层一页、每条先摆 3 条回复，剩下的写「还有 N 条回复 · 点开」。
  小红书首页每条评论只给 1 条回复预览（站上可能是几十条），点开那一行会真去
  `/api/sns/web/v2/comment/sub/page` 再取一批，接着点就接着取。
- 表头那个「回复 X」是**站上真实的收件人**：小红书的子评论是平铺的，一条回复
  常常在回另一个子评论作者，就写那个人的名字，不会一律算成楼主。
- 知乎按问题、回答、回答的评论三层组织，其余来源为帖子与评论。
- 知乎的评论走 `root_comments`：顶层只摆顶层，回复摆在各楼下面（`/comments` 会把回复
  平铺进顶层，一页 20 条里能有 17 条是回复）；「还有 N 条回复」按站上的
  `child_comment_count` 算，是准确数字。
- 知乎的回答详情一页摆 **20 条**顶层评论，往下读能接着取——`root_comments` 的
  `paging.is_end` **永远是 true**（实测一条 171 条评论的回答：offset 0/20/40/60 每次
  都回来 20 条新的，`is_end` 四次全 true），拿它判"到底了"就只有第一页，
  所以改看"这一页有没有满"。问题页里每条回答仍只带 8 条预览（点进去才是整页）。
- 问题页里每条回答下面只带 8 条评论预览（一屏 6 条回答，每条都摆 20 条会撑成 120 条），
  但会写「还有 N 条回复 · 点开」——点开续的是**这条回答的**评论，一次 20 条；
  翻到底之后那个 N 会校正成顶层真数（站上的 `comment_count` 是"评论 + 回复"的总数）。
- 知乎的**推荐**（和关注）是「流」不是榜单：每次切进来都是新的一批，不吃列表那 5 分钟缓存；
  进来后顺手把后面两页预取到本地，往下翻的时候就不用等（热榜相反，5 分钟那份才是对的）。
- NGA 会把一部分帖子的 JSON 发一半就断掉（2026-10-23 实测：晴风村 + 水区 80 条里 27 条），
  这时改读同一帖的 HTML 页面——正文和回复照给；两条路都不行才报"回包被截断"，
  不会含糊地说"接口坏了"。NGA 的正文换行是 `<br/>`，按行分段，不挤成一坨。
- **搜索**：按 `F` 弹出输入条，回车确认，`Esc` 退出搜索（回到原来那一栏），`Z` 照样能撤回。
  结果单独成一栏「搜索：关键词」，页脚也写着它；切板块、切社区会把这个词一起扔掉——
  否则新栏目还在按上一个词搜，看起来就像"这个板块只有这几条"。
  能搜的：知乎（`search_v3`，要 Cookie；只收**回答**，问题和用户点开是空白所以不摆）、
  NGA（`thread.php?key=`，要 Cookie）、豆瓣小组（网页搜索页，匿名可读）、
  小红书（`/api/sns/web/v1/search/notes`，要 Cookie 和签名）、GitHub
  （`api.github.com/search/repositories`），以及**混流**（把能搜的几家一起搜，只出第一页）。
  IT之家、微博、虎扑、linux.do、Medium 和自定义 RSS **没做**：按 `F` 会照实说测到的原因
  （2026-11-02：`so.ithome.com` 连不上且 `www.ithome.com/search/` 404、
  `m.weibo.cn` 回 432 要登录、`bbs.hupu.com/search` 的 GET 和 POST 都是 405、
  linux.do 的 `/search.json` 被 Cloudflare 挡、Medium 同理），不弹一个搜不出东西的框。
- 读到最底下会**自动接着取**：列表滚到底续下一页；帖子详情里评论（知乎的问题页就是回答
  列表）滚到底也续下一页；评论到头了再接着取「还有 N 条回复」里的子评论（知乎、小红书）。
  页面比一屏还短、滚不动时，按 `↓` 停在最后一条再按一次也会接着取；来源说没有了就一个
  请求都不再发
- 内容为只读，不提供发帖、回复、点赞等写操作。
- 小红书点进去的那一页**不摆图**：正文只出文字，连 `[图]` 占位也没有，图也不下载
  （列表里仍有封面）。
- 部分来源需要登录凭据才能读取正文与评论，可在设置中填写，或从本机浏览器导入。
- 豆瓣的栏目是**讨论精选 + 话题广场 + 六个小组**（小组和话题都是豆瓣的板块）：按 `.` 在它们之间轮；
  「话题广场」那 20 个话题走的是**豆瓣 App 的 rexxar 接口**（`m.douban.com/rexxar/api/v2/...`）——
  网页端 `/gallery/`、`/explore/` 对匿名一律 403，手机站的 HTML 也 403，**只有手机 UA 打这个 JSON
  接口是通的**（不带 Cookie、也不用 apikey）。挑一个话题 = 只看这个话题下的动态（首页「热门话题」
  也是同一个接口渲染的，所以这就是手机端那套推荐内容）。注意：**「浏览发现」和 App 的"推荐"流
  没有能匿名取到的接口**（`/explore/` 403、猜的几个推荐流路径全是 404），这一版没做。
  板块选择器里还会多出「热门小组」那一页的 20 个（名字和 id 都从卡片上解析）。
  小组讨论页一页 30 条平铺（置顶另加），标题取的是 `title` 属性（页面上那个是截断版），
  作者/回应数/最后回复时间都拆得开——注意那个时间是「10-19 09:47」这种**没有年份**的写法。
  讨论精选是**跨小组的热帖合集**（一页 29 条，`?start=` 真能往后翻）：列表**免登录**就能刷，
  每条带着来自哪个小组、多少「喜欢」、封面和摘要。点进话题要登录——豆瓣对匿名一律
  403「没有访问权限」（本机实测：换三个不同小组、换 UA、换出口 IP，结论一样），所以那一步
  照实说"要登录"，不装成"取数失败"（列表本来就在，人也没断网）。在设置里贴一次豆瓣
  Cookie，正文和回复就都能看；没贴的时候右上角写着「Cookie 未配置（这个来源要登录）」。
  反过来，**列表页带 Cookie 会被挡**：实测同一个 `group/explore` 匿名 200（29 条），
  带上 Cookie 就变成 1206 字节「禁止访问」（+腾讯验证码），所以这个来源的列表走匿名、
  正文/回复才带 Cookie。真被风控挡下来时页面上直说是被挡了、过几分钟再试，
  不赖成「改版了」、也不说成「要登录」（那是两回事）。
- 虎扑的栏目顺序是**战绩 / 赛程 / 步行街 / 湿乎乎**打头，后面才是篮球场这些专题板，
  再往后是全量目录（255 个板，按 `V` 一路往下、打字能筛）。
- 虎扑除版块帖子外还有两栏：**NBA 战绩**（东、西部各一张榜，点进去是整张排名表）与
  **NBA 赛程**（赛程里每场一条，列表里直接写比分和"进行中 第三节剩5:57 / 已结束"）。
  点进一场，**标题就是比分**（`老鹰 132 - 125 魔术`；进行中还会带"第四节剩5:22"，那个数字
  每 5 秒在变），正文直接从分节比分表开始——比分、开赛时间、「数据统计」抬头都不再重复第二遍，
  元信息那行只剩 `10月22日 星期四 07:00 · 数据统计`。按 `T`（或右键菜单里的那一项）在
  **文字直播**（逐回合）和**数据统计**（分节比分、全队命中率与篮板助攻、每个上场球员一行）
  之间来回切，标签上写着当前是哪一页；同一场切过去再切回来还在原处。
  已经打完的那场，点开给的是**赛后帖**：虎扑湿乎乎里那条 `[赛后]老鹰132-125魔术，…`，
  标题换成它的标题，下面是这条帖的回复（作者、亮数、正文）。主楼是虎扑的比赛卡片
  （一段 JSON，实际内容是一张 H5），不是文字，跳过不显示。
  赛后帖按"客队 + 比分 + 主队"对上，**找到一次就记住**，下次点开直接给、不再翻湿乎乎；
  翻不到（刚完场还没发帖）就仍旧给文字直播，过十分钟再试一次。
  战绩、技术统计、逐回合都排成表格（列对齐、数字右对齐）。技术统计 17 列一个不砍、
  **按重要程度从左往右排**（球员/得分/篮板/助攻/时间在前，投篮细节和位置在后），
  右边看不全就左右滑——`Shift+滚轮` 或左右箭头，不显示横条。全队汇总在每队最前面。
  比赛进行中时详情每 5 秒自动重取（节间、中场也算在打），赛程列表里的比分每 20 秒自己补一遍，
  打完停表前还会补最后一次；标题里的比分跟着变。
  站点会同时挂着好几份年龄不同的副本（同一个比赛能取到相差好几分钟的两份），所以比分**只往前走**：
  比屏幕上旧的那份直接丢掉，切走再回来、按 `R` 刷新都不会退回去。
  它自己也按批重排，所以是"站点一变，5 秒内就能看见"，做不到比站点更实时。两栏都是公开页面，不需要登录。
- 社区页的**有图 / 无图**（低调显示）就是一个字母 `E`，设置里能改；写成 `ctrl+alt+l`
  这种组合就变成全局热键（窗口在后台也能按），单个字母只在窗口里有焦点时生效——
  否则你在任何程序里打这个字母都会翻一次图。
  无图时图片位置是 `[图]`，图一个字节都不下载（省流量也更快）；切回有图会把手边那份换个新的，
  图片立刻回来。
- 阅读页滚到顶/底时**接上下文**：往上到顶会把前一段渲染出来，原来那一行还留在屏幕上，
  接着往上滚就是连续的文字（往下到底同理），不会忽然跳一整页；换章只给翻页键
  （空格、PageUp、PageDown）。一次滚多少行在设置的「滚动行数」里调：**滚轮一格和方向键一下
  走的是同一段距离**（设 2 行就是 2 行，拉窗口、换字号都不变；滚得再快的鼠标也只算一格，
  触摸板按真实滑动距离走）。
- 微博两栏：**热搜**（榜单词条，免登录）和**关注**（关注时间线，一条是一条帖子）。
  「关注」必须有**当前有效**的登录 Cookie：weibo.com 让你走「新浪通行证」验证的时候，
  这一栏会照实说「微博说没登录（ok=-100）」，不拿空列表装没事。点进热搜词条后的正文也要
  Cookie（只取该词条下最新的几条文字）。

### Anki 卡片

- 通过 AnkiConnect 与本地 Anki 通信，卡片以文档形式显示，使用键盘评分。
- 可将 Anki 自身窗口隐藏，退出该模式时恢复。
- 卡片内容不写入日志，也不保存到磁盘。

### 显示控制

| 功能 | 说明 |
| --- | --- |
| 老板键 | 隐藏或显示窗口，阅读状态完整保留，热键可自定义 |
| 偷瞄 | 不抢占焦点地显示窗口，并把鼠标滚轮接过来滚正文（一格走设置里的行数，和窗口内完全同一步长）；滚动事件不会传递给下层窗口。鼠标点一下任务栏就当场收起来——那是要去换程序了；左键平时照常放行，只有落在任务栏上才算“要走”；**在自己窗口里按右键 = 弹书页那份右键菜单，人不退出偷瞄**：菜单就弹在鼠标那一点。（钩子给的是物理像素，Qt 的窗口坐标是去掉缩放的逻辑像素——192 DPI 这台机器上差两倍，直接喂物理坐标会被判成“在屏幕外”贴到右下角；现在按落在哪块屏、乘除各自的缩放比。）菜单开着时按键只给菜单，Esc 只关菜单、不会把窗口收走。右键落在别的程序上才是老规矩：收窗口、放行。菜单和窗口一样带 `WS_EX_TOPMOST`——正文页是常驻顶层，菜单不顶层就会被它盖住（cq / ce 都遇到过“菜单弹了却看不见”）。（原来还有一条“前台换了进程就自动收”，2026-11-10 按使用者的要求删掉了：看资料时来回切窗口太频繁，书页动不动就没了） |
| 自动配色 | 取窗口旁侧的屏幕颜色作为背景，并按亮度选择文字颜色（黑/白之间带迟滞，亮度在临界线附近飘也不会整页翻色）。设置里可勾「背景用实色」：同一颜色铺满、不透明，背后什么都看不见。取色每 0.5 秒看一次，**颜色没变就不重刷样式**——不会每半秒把整页正文重排重画一遍 |
| 幽灵模式 | 鼠标离开窗口后文字透明，移入即恢复（书页、社区页、卡片页都一样）。融景开了「背景用实色」时，整扇窗一起淡到几乎看不见——底色不透明，只藏字会剩一块实色空白 |
| 防截屏 | 调用 `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`，窗口不出现在截图与录屏中，需 Windows 10 2004 及以上 |
| 安全文档 | 将内容切换为内置工作文档或指定文件，退出后恢复原内容 |

## 托盘菜单

右下角任务栏角（`^` 溢出区）那个白色书签图标上右键：

| 项 | 作用 |
| --- | --- |
| 显示/隐藏（老板键） | 跟热键一样 |
| 隐形背诵 / 社区统一流 | 进那两个模式（快捷键见下） |
| 叫回 Anki 窗口 | Anki 被别的窗口埋到后面时把它捞回来 |
| 打开本地书籍… / 设置… | 老样子 |
| **重新启动** | 先存好进度和窗口位置，再起一个新进程接上，最后老进程退场 |
| 退出 | 退出 |

"重新启动"不会撞上单实例保护（双开会让两个进程同时响应老板键、互相覆盖进度）：老进程把自己
的 pid 传给新进程，新进程**先等它真的退出**再去抢互斥体；新进程要是起不来（比如刚改坏了代码），
老进程就不退，程序不会凭空消失。整个重启大概两秒，托盘图标换个 pid 继续待在原处。

### 锁屏解锁之后

每次锁屏再解锁，程序会**在后台静默重启一次**，而且起来是**藏着**的（不会在你解锁的瞬间弹到屏幕上）：

- 为什么重启：锁屏期间 Windows 会摘掉低级键盘钩子、把窗口丢到屏幕外，解锁后靠原地修补总有漏网的。
  重启以后钩子、窗口摆放、显示配置全是新的，最干净。
- 进度和窗口位置不会丢：退出前先把**视口顶那一行**记成进度、把窗口位置写进 `config.json`，
  新进程启动时原样接回（日志里能看到"重启前已记下进度 N、窗口位置 (x, y)"，紧接着
  "应用启动（解锁后台重启，保持隐藏）"和"恢复阅读进度: … @ N"）。
- 解锁通知成串来的时候二十秒内只重启一次；有弹窗开着、或者正在隐形背诵（重启会惊动 Anki 窗口）
  就跳过这一次，日志里写明原因。
- 不想让它这么干：`config.json` 里把 `restart_on_unlock` 设成 `false`。

## 安装

### 预编译版本

从 Releases 下载 `StealthReader-1.1.0-win64.zip`，解压到任意目录后运行 `StealthReader.exe`。不需要安装 Python 或额外依赖。

程序将配置、缓存与日志写入自身所在目录，整个文件夹可直接复制或删除。

若全局热键不生效，请以管理员身份运行：部分系统策略会限制普通权限进程注册全局键盘与鼠标钩子。

锁屏（`Win+L`）之后再按热键没反应，是 Windows 这一侧的两种老毛病，程序里都处理了：

- 锁屏那一刻的**松键事件进了安全桌面**，钩子库以为 `Win` 还按着，于是所有组合键都匹配不上。
  现在每按一下键都会对照物理键位把这类"其实早松了"的修饰键擦掉，所以**解锁后第一下就管用**。
- Windows 会在回调超时后**悄悄摘掉低级键盘钩子**，库自己还报"一切正常"。现在除了看门狗定期重挂，
  还多了一条物理轮询（每 180 毫秒查一次真实键位）：钩子没了，老板键照样能把窗口叫回来，
  日志里会写一行"热键钩子没反应，改用物理轮询"。

日志里能看到兜底盯着哪几个键（"钩子掉了也能叫回来（物理兜底盯着）: …"）。

还有一种"按了没反应"根本不是热键的问题：**窗口在屏幕外**。实测见过窗口停在 x = -1890——
正好比记着的位置往左一整屏，Windows 却照样说"可见"（日志里"显示窗口"写得清清楚楚，
屏幕上什么都没有）。

现在的做法（2026-10-21 重做，起因是"叫不回来，而且一闪一闪"）：

- 两个信号都问：Qt 的 `_rect_usable`（和 `move` 同一套逻辑像素）与 Win32 的
  `MonitorFromWindow(MONITOR_DEFAULTTONULL)`（不带缓存）。**任一**说看不见就当看不见。
- 摆的时候**只用 Qt 的 `setGeometry`**。以前用 Win32 的 `SetWindowPos` 挪、再把物理像素除以
  dpr 同步回 Qt，两套坐标一打架，窗口就在"屏幕外"和"拉回来"之间来回跳——人看到的就是一闪一闪。
- 摆完 260 毫秒复核一次，还不行才让 Win32 硬挪一次；然后**安静 30 秒**，连续两次摆不好安静
  五分钟。所以最坏情况下人也只会看到窗口跳一次，不会在屏幕上抽。
- `WM_DISPLAYCHANGE` / `WM_DPICHANGED`（插拔显示器、改分辨率、改排列、改缩放）一到就重摆一次，
  这才是"锁屏/换显示器之后叫不回来"的源头事件。
- 每 5 秒一次的定时复核只在"看着可见、其实不在任何屏幕上"时动手，并写一行
  "窗口搬到记住的位置 (30,30)：Qt 与 Win32 都说不屏幕上"。


### 从源码运行

要求 Windows 10/11 与 Python 3.12。

```
pip install "PyQt5==5.15.*" keyboard requests
python main.py
```

`cryptography` 或 `pycryptodome` 为可选依赖，仅用于解密 Chromium 系浏览器的 Cookie。

`run_stealthreader.cmd` 是日常用的启动器（桌面快捷方式指向它）。它不假定 Python 装在哪，
而是挨个试：`%APPDATA%\WPS*\python-env` 里的 pythonw/python、`%LOCALAPPDATA%\Programs\*`
自带 office runtime 的解释器、以及 PATH 上的 pythonw/python。每个候选都要**真的跑**一次
`import PyQt5.QtWidgets, requests` 并写出一个标记文件，写不出来的跳过——只看"文件在不在"
是不够的（见 `docs/community-feed-design.md` 9.aq）。选中哪个会在窗口里回显一行
`[StealthReader] using …`，程序自己的"重新启动"也复用这个选择。

程序只许跑一个（双开会互相抢老板键、互相覆盖进度）。已经在跑的时候再点一次快捷方式，
第二个进程不会只丢下一句"已经在运行了"就走：它用一个命名事件通知里面那个把窗口**亮出来**
（`StealthReader_Wake`），日志里能看到"单实例：已经有一个在跑，已叫它把窗口亮出来"和
"启动器叫醒：把窗口亮出来（之前可见=…）"。

## 使用

首次运行会在程序目录生成 `config.json`，各项设置保存在其中，也可以在设置界面修改。

- **书籍**：右键「本地书架」挑一本接着读（双击），或「打开本地书籍」选一个 TXT / EPUB 文件。把书扔进程序目录的 `books/` 也会出现在书架里。
- **社区**：按 `Ctrl+Alt+F` 进入。需要登录的来源在设置中填写 Cookie，或使用 Cookie 导入功能。
- **卡片**：需要本地 Anki 正在运行，并安装 [AnkiConnect](https://ankiweb.net/shared/info/2055492159) 插件。安装后按 `Ctrl+Alt+A` 进入，可在设置中选择牌组。

## 配置

`config.json` 中的常用项：

| 键 | 说明 |
| --- | --- |
| `opacity` `font_family` `font_size` | 窗口透明度与正文字体；`font_size` 单位是**像素**（默认 19），和社区页 `feed_font_size` 同一套单位 |
| `line_spacing` `paragraph_spacing` `page_margin_chars` `first_line_indent` | 排版参数 |
| `page_overlap_lines` | 翻页时保留的上一页行数，默认 2；设为 0 则新一页从上一页的下一行开始 |
| `arrow_scroll_lines` | 每次滚动的行数，上下箭头、窗口内滚轮、偷瞄滚轮共用，默认 3。只有像素的那种滚轮（触摸板/高精度滚轮）也折成同样的行数，不会一处一格 1 行、一处一格 3 行 |
| `boss_key` `peek_key` `safe_key` `anki_key` `feed_key` `solid_key` | 六个全局热键；`solid_key` 是实色开关，默认 `ctrl+alt+b` |
| `safe_doc_path` | 安全文档使用的文件，留空则使用内置文档 |
| `anki_deck` `anki_conceal` `anki_api_key` | 默认牌组、是否隐藏 Anki 窗口、AnkiConnect 密钥 |
| `feed_sources` `feed_rss` | 启用哪些社区来源，以及订阅地址 |
| `ghost_mode` `auto_mode` `antishot_mode` | 幽灵模式、自动配色、防截屏 |
| `show_corners` | 自动配色（融景）模式下左上/右下那两道角标；开着也只有鼠标凑近那个角时才露出来 |
| `auto_bg_solid` | 自动配色的实色档：背景用采到的颜色、alpha 255；默认关（老档 alpha 2，几乎全透）。热键 `ctrl+alt+b` 可随时开关，设置里也能改这个键 |

站点凭据保存在程序目录的 `feed_auth.json`：

```json
{
  "zhihu": { "cookie": "...", "user_agent": "..." }
}
```

## 数据与隐私

程序不收集使用数据，也不向作者或第三方发送统计信息。访问网络仅发生在以下情况：打开社区页、启用 Cookie 导入。书和书架都不联网。

程序目录中会生成以下文件：

| 文件 | 内容 |
| --- | --- |
| `config.json` | 设置 |
| `annotations.json` | 高亮、笔记与书签 |
| `reading_stats.json` | 阅读统计（按天 / 按书 / 会话表），不含书的内容 |
| `feed_auth.json` | 各站点登录凭据 |
| `cache/` | 社区内容与图片缓存 |
| `stealthreader.log` | 运行日志，不含卡片内容 |

`feed_auth.json` 为明文 JSON，其中的 Cookie 等同于对应站点的登录状态。该文件已在 `.gitignore` 中排除，请勿分享或提交。

## 已知限制

- 仅支持 Windows。
- 社区部分为只读，且依赖各站点公开接口，接口变动或风控收紧时可能需要更新 Cookie 或等待适配。
- 书架只管本机的 txt / epub / md：没有网络书源，也没有在线章节。
- 提供的是压缩包而非安装程序，也不包含自动更新。
- 窗口是逐像素透明的分层窗口（融景透底、幽灵淡出都要它），所以正文是**灰度抗锯齿**，用不上 ClearType 的次像素渲染（实测窗口内彩色边缘像素 0.00%，系统 ClearType 是开着的）。在实色档下这条最容易被看出来：笔画比别的程序略“软”。要 ClearType 就得改成不透明窗口，代价是融景透底和幽灵淡出都得换实现。

## 测试

`tests/` 下的探针脚本在离线状态下运行：网络层被替换为固定响应，适配器只读取 `tests/fixtures/` 中裁剪过的真实响应样本，因此不需要网络与登录状态。`probe_live.py` 会实际发起请求，仅在需要时手动运行。
