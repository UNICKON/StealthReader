# 🐟 Stealth Reader (摸鱼阅读器) - Python版

**Stealth Reader** 是一款专为“上班摸鱼”打造的桌面阅读工具。它基于 PyQt5 开发，具有极高的隐蔽性，支持**本地 TXT 阅读**和**手机端 [Legado](https://github.com/gedoor/legado) (阅读APP) 同步**。

无论是在深色 IDE 背景下，还是在复杂的桌面环境中，它都能完美融入，助你神不知鬼不觉地修仙。

## ✨ 核心特性

### 🛡️ 极致隐蔽

- **透明背景 & 无边框**：窗口完全无边框，背景透明度可调，文字仿佛直接印在屏幕上。

- **👻 幽灵模式 (Ghost Mode)**：鼠标移开窗口时，窗口自动变透明/隐藏；鼠标移入时自动显现。

- **🦎 变色龙模式 (Auto Mode)**：自动吸取窗口下方的屏幕颜色作为背景色，并自动反转文字颜色，完美融入任何环境（如 IDE 代码区、网页背景）。

- **🛡️ 系统级防截屏**：开启后，**截图、录屏、腾讯会议、Zoom 共享屏幕时，窗口完全不可见**（透明），只有你的肉眼能看到。

- **老板键 (Boss Key)**：一键隐藏/呼出窗口（默认为 `Esc`，可自定义），系统托盘同步隐藏。

### 📚 强大的阅读功能(推荐配合阅读APP使用)

- **📂 本地 TXT 智能阅读**：
  
  - **自适应分页**：不依赖死板的字符数，而是根据当前窗口大小几何计算分页，调整窗口大小后自动重排，文字永远填满窗口。
  
  - **进度锚点**：调整窗口或重启软件后，精准定位到上次阅读的第一个字，绝不迷路。
  
  - **编码兼容**：自动识别 UTF-8 和 GBK 编码。

- **📱 Legado (阅读APP) 同步**：
  
  - 利用“阅读APP”的 Web 服务接口，同步手机书架。
  
  - 支持目录跳转、搜索书籍。
  
  - **双向进度同步**：电脑看一半，手机接着看。

## 📖 使用指南

### 1. 基础操作

- **移动窗口**：按住文字区域即可拖动。

- **调整大小**：鼠标移动到窗口**右下角**，光标变化后拖动调整。

- **鼠标光标**：正文区光标**始终是箭头**，不会变成输入框那种 I 形——这是个读书窗口，不是编辑框（文本仍可拖选划线）。只有右下角缩放区、中键/Alt+左键拖动时才是缩放/移动光标，松开即回箭头。实现见 `ReaderTextEdit`（见「偷瞄模式」一节的说明）。

- **翻页**：
  
  - 鼠标滚轮
  
  - 键盘方向键 `↑` `↓` `←` `→`
  
  - 空格键 `Space` / `PageUp` / `PageDown`

- **右键菜单**：在窗口任意位置**右键**，可打开功能菜单（设置、书架、打开本地文件等）。

### 2. 打开本地 TXT

1. 右键菜单选择 **“📂 打开本地 TXT”**。

2. 选择文件后，软件会自动加载。

3. **特性**：你可以随意拖拽改变窗口大小，软件会自动重新计算当页内容，保证阅读连贯性。退出时会自动保存进度。

### 3. 连接 Legado (阅读APP)

如果你想看手机上的书，请按以下步骤操作：

1. 手机端打开 **“阅读” (Legado)** APP。

2. 点击 **“我的” -> “Web服务”**，开启服务。

3. 记录手机上显示的 IP 地址和端口（例如 `http://192.168.1.10:1122`）。

4. 在电脑端本软件上 **右键 -> ⚙️ 设置**。

5. 在 **Legado地址** 栏输入手机上的地址。

6. 保存后，右键选择 **“📚 网络书架”** 即可同步。

### 4. 隐蔽模式详解

在 **设置** 中可以开启以下模式：

- **🦎 自动挡 (变色龙)**：推荐开启。窗口背景会变成你壁纸或底层软件的颜色，文字自动变色。放在 VSCode 代码里就像注释一样。

- **👻 幽灵模式**：适合极其危险的环境。平时窗口几乎完全透明（看不见），只有当你假装移动鼠标经过该区域时，文字才会显现。

- **🛡️ 系统级防截屏**：利用 Windows API (`SetWindowDisplayAffinity`)。开启后，你截图发给同事，截图中该区域是空的/透明的，看不到小说内容。

## 📚 本地 epub 支持（本机增补，非上游功能）

在原版基础上就地增加了 epub 支持，只用 Python 标准库（`zipfile` + XML/HTML 解析），没有引入新依赖：

- **打开方式**：右键菜单 → `📂 打开本地书籍 (TXT/EPUB)`，文件对话框新增 `*.epub` 筛选。
- **解析范围**：epub 2（`toc.ncx`）和 epub 3（`nav.xhtml`）的目录都能读；正文按 `spine` 顺序抽取，剥离标签/脚本/样式，保留段落与列表的换行。
- **目录跳转**：右键菜单 → `📑 本地目录`（仅当前是 epub 时可用），双击章节跳到该章开头；阅读进度按字符偏移记录，重启自动续读。
- **目录是多级的（不再只认一级）**：epub 3 的 `nav.xhtml` 按 `<ol>` 嵌套深度算层级，epub 2 的 `toc.ncx` 按 `navPoint` 嵌套深度算层级，**卷 / 部 / 章 / 节都提取**；书里 `h1`–`h6` 的小标题也一并收进目录（级别取标签编号，标题取那一行原文，空行或超过 80 字的不算标题）。目录页按层级用全角空格**缩进显示**，`Ctrl+L` 一眼能看出结构；导出的 Markdown 也按层级给 `#`（1 级 `###` → 2 级 `####` → 最多 `######`）。层级会归一化到从 1 起（有的书目录整棵从第 2 层起，不归一化会整体歪一格）。txt 没有结构信息，按 `第X卷/部/篇` 记 1 级、`第X章/节/回` 记 2 级来猜。
- **标题清洗**：部分 epub 会把插画说明混进目录标题（Gutenberg 版常见），以 `CHAPTER XXVII`、`第 12 章` 结尾的章节号会被单独取出。
- **已知限制**：
  - 只取**文字**：配图、图注、表格排版会丢失；纯图片书（漫画）会提示"epub 里没有可读文字"。
  - 只记住**最近一本书**的进度，换书后上一本的位置不再保留。
  - 目录偏移基于解析后的文本，若 epub 文件本身被替换或改动，旧进度会错位。
  - 本地模式没有原生章节分页，翻页仍沿用按像素几何计算的方式。

## 📐 行距 / 段间距 / 页边距 / 首行缩进（本机增补，非上游功能）

- **在哪调**：右键 → `⚙️ 设置`，全部**拖动即时预览**：
  - `行距`：80%–250%（相对行高）→ `line_spacing`
  - `段间距`：0%–200%（同样以行高为基准）→ `paragraph_spacing`
  - `页边距`：0–3 **字**，四边同一个值（1 字 = 一个全角空格宽 = 当前字号下一个汉字的宽度，随字号字体等比变化：14pt 新宋体下 1 字 ≈ 19px）→ `page_margin_chars`
  - `段落缩进`：勾选框，给每个自然段的第一行加缩进 → `paragraph_indent`
  - `首行缩进`：缩进多少，0–4 字符（1 字符 = 一个全角空格宽，随字号字体变化）→ `first_line_indent`
- **四边量的是同一个东西（正文墨迹）**：顶部/左右是固定视口留白，底部按末行墨迹收边，所以量出来四边是齐的（实测 14pt 新宋体、页边距 12px：上 13px / 左 12px / 右 11.5px）。三处曾经让它不齐，都已修：
  - **左边多 5px**：正文外框（`content_frame`）的布局留白 `setContentsMargins(5, 0, 5, 0)` 只加在左右两边，等于凭空多 5px，已改成 0（外框圆角是 5px，但页边距至少几像素，正文不会压到圆角上）。
  - **右边参差**：中文不做两端对齐时，一行排不下再一个整字，末尾就留一段空白，且视口宽除不尽字宽的那几像素永远用不上（当前字号下 480 mod 19 = 5px）。现在段落一律**两端对齐**（`QTextBlockFormat.setAlignment(Qt.AlignJustify)`），满行拉到右边缘（实测同一段 14 行：左对齐时右端 372–399，两端对齐后全是 405 = 视口宽）。段末短行仍然短（Qt 不拉伸段落最后一行），标题是单行块也不受影响。注意**这本书段落短，多数行本来就是段末短行**，所以两端对齐在长段落的书上才明显。
  - **顶部多 0–4px**：那是首行墨迹顶到行盒顶的空白，取决于这页第一个字（汉字顶格，标点/拉丁字母低一点），不是留白本身。
- **实现方式**：Qt 样式表里没有 `line-height` / `margin` / `text-indent` 这类排版属性，所以行距、段间距、首行缩进都写进文本块格式（`QTextBlockFormat.setLineHeight / setTopMargin / setTextIndent`），**页边距四边都用视口留白**（`QAbstractScrollArea.setViewportMargins`，文档留白 `documentMargin` 归零），底部再按页收一次边（见下条）。每换一次文本重新套用一次，翻页探测也走同一套。
- **四边都留白（顶部为什么必须用视口留白）**：左右和顶部原来靠 `QTextDocument.documentMargin`，那是**文档内部**的留白——内容一滚就跟着滚走，偷瞄用滚轮平滑滚动时顶部那条留白被文字顶掉，看着就是"底部有页边距、顶部没有"。改成视口留白后它是个**固定的框**，滚动吃不掉，上下对称。
- **底部收边（末行不被切半行）**：正文是按几何切页的，切点落在哪一行就显示到哪，**压在窗口下沿的那一行会被切掉半行**，这是原来"底部没有页边距"的真正原因。现在渲染完一页会把正文区底边收到**本页最后一个完整行的墨迹下沿**（行矩形 + `QTextLine.leading()`，把行盒里那几像素行距补回给裁切量）：末行完整、下面是一条空白，被裁掉的那一行整行留给下一页。判"这一行算不算完整"用的是**墨迹**下沿而不是行盒下沿，所以留白能小到刚好等于设定值，不会为几像素空隙把整整一行推给下一页（实测 30 页里有 1 页因此多挤进一行，底部留白从 42px 掉到 14px）。裁切线只跟行位置有关，**不会因为裁切而丢字或重复**（实测整本 190 页翻完，各页可见文字拼接与全文逐字相等）。
- **底部不可能和左右一样平**（除非做"每页垂直撑满"）：一行的墨迹是整块出现的，页面高度切不出整数行，剩下那截只能留白，所以底部空白 = 设定值 + 0～一行（实测 20 页：13～45px，均值 29px，而顶部 13px 恒定；页边距 0 时完全退回原来的行为）。要做到四边严格相等，只能按页把 N 行撑满（把余量摊进行距，每页行距漂移 ≤4%），那是另一种排版取向，本机没做。
- **一个 Qt 坑**：`setViewportMargins` 改完留白，Qt 会顺手把竖直滚动条甩到文档末尾（画面停在页尾）。所以每次渲染完一页、算完留白后会**再钉一次页首**（`verticalScrollBar().setValue(0)`），并作为不变量校验（翻页 / 划线 / 进出偷瞄 / 改字号后滚动值都必须为 0）。
- **"标题"是怎么认出来的**：正文是一整串纯文本，没有样式可言，所以标题只能靠字符偏移查表。标题不缩进是**自动**的，界面上没有这个开关（只有 `heading_no_indent` 这个配置项留给 txt 猜错时手动关）：
  - epub：解析时记录书里 `h1`–`h6` 所在行，再加上目录标题所在行（清洗过的标题只用于显示，偏移取原文位置）。
  - txt：没有结构信息，只能按字面规则猜——以 `第X章` / `CHAPTER X` / 序、前言、引子、导读、目录、版权……打头，且整行不超过 40 字、不以句末标点结尾。
- **页首那一块不缩进**：翻页是按像素切的，一页的第一块常常是上一段的后半截，给它加缩进会读起来像新起了一段。判定办法是看它在全文里的前一个字符是不是换行。
- **和翻页的关系**：四项一改，一屏字数自动变少（实测行距 100→200% 时 354→162 字；页边距 0→2.5 字时 354→264 字；段间距 0→100% 时 253→129 字；首行缩进 0→4 字时 354→333 字），前后翻不会错位。
- **两点注意**：段间距遇到"每行都是硬换行"的 txt，会看起来像额外的行距；页边距和首行缩进在很窄的窗口里会明显挤掉每行字数。
- **改了就生效，而且真的留得住**：设置里拖 行距 / 段间距 / 页边距 / 首行缩进 / 字号 / 字体 都是**拖动即预览**，并**立刻写进 `config.json`**；「保存并应用」= 再排一次 + 落盘，点「取消」把预览值退回去（以前取消也会把预览偷偷留下）。这里原来有两个坑，表现都是"页边距调整不生效"：
  - 预览只改内存、从不落盘（`on_typography_change` 不写文件、`accept()` 也不写），所以只要**没点保存就退出/崩溃/被重启**，值就悄悄退回文件里旧的那个——改的时候看着对，下次打开又变回去。
  - `apply_style()` 里那句"本地模式重绘页面"原来只写在**非自动挡**分支里，自动挡（变色龙）下改页边距/字号不重排，得等下一次翻页才生效；字号/字体更是连 `valueChanged` 都没接（只在保存时才读）。现在重排挪到分支外，字号字体也接上了实时预览。
- **默认值**：`行距 100% / 段间距 0% / 页边距 1 字 / 首行缩进 2 字`，`标题不缩进` 默认开。页边距和首行缩进默认不为零（中文书籍习惯），不想要就调到 0；旧配置缺这些键时按默认处理。**老配置里的页边距是像素**（键名 `page_margin`，0–60px）：首次启动会按当前字体换算成"字"（12px ÷ 19px ≈ 0.63 字）并固化到新键 `page_margin_chars`，观感不变；换字号时页边距才跟着等比走。

## 👀 偷瞄模式（Ctrl+E，本机增补，非上游功能）

- **怎么用**：按一下 `Ctrl+E`（可在设置里改 `偷瞄热键`），书页浮现——**不抢焦点**，你手头的工作窗口照常打字。此时鼠标**不用挪到书窗上**，滚轮在任何位置都能读：**一格滚约 3 行**，和鼠标放在窗口内滚动的手感像素级一致（实测窗口内一格 60px）；滚到 5000 字缓冲区底部会无缝衔接下一屏（从当前视口顶部续起，不跳字），滚到顶部同理向前翻。
- **怎么退出**：敲键盘任意键、**右键 / 中键**点一下、再按一次 `Ctrl+E`，任一即退出；**退出就把窗口收起来（隐藏）**——偷瞄是"临时看一眼"，看完就该从屏幕上消失。要再叫出来：`Ctrl+E` 继续偷瞄，或老板键 / 托盘图标把窗口显示出来。**左键点击不退出**——偷瞄时照样能点工作窗口、拖选区、按按钮，只有键盘和右键/中键才收工。鼠标移动、光标滑过书窗不算退出输入。
- **偷瞄里双击正文 = 进入安全文档**：偷瞄时拿不出安全文档就麻烦（有人过来了）。双击正文即刻换成安全文档（窗口继续亮着、位置不变），也就是 ce → cd；反过来按 `Ctrl+E` 进偷瞄时如果正在安全文档模式，会**先把真书放回来**再浮现（cd → ce 看到的是书，不是那份假页面）。退出偷瞄一律隐藏，**不会退回安全文档**那副页面。
- **滚轮是"吞掉"的**：偷瞄期间滚轮只翻书页，底下正在用的文档/网页不会被滚动——不会因为文档自己动了而穿帮。偷瞄热键本身在模式中也会被吞掉，不会落到当前应用上。
- **偷瞄期间正文照常可用**：左键已经不退出偷瞄了，所以正文区不再吞鼠标事件——偷瞄时能正常**拖选文字**（选区、`复制选中文字`、划线的确认面板都照常），**点一下**也不会退出偷瞄（点在已划线上照样出那条高亮面板）。想在偷瞄里顺手划一条线也行；只有键盘和右键/中键才收工。
- **鼠标光标不是输入状态**：正文区虽然能拖选，但光标**永远是箭头**，不会变成 I 形（`QTextEdit` 只要文本可选中就会自己把 viewport 光标设成 I 形，所以每个入口之后都把想要的形状压回去：鼠标事件 / 悬停 / 进入 / 聚焦 / 换文本 / 改交互标志）。右下角缩放区、中键拖动时临时换成对应光标，松开就回箭头。
- **幽灵模式自动让路**：偷瞄期间光标不会进入书窗，幽灵淡出被临时抑制，退出后恢复。
- **实现**：`ctypes` 挂 Windows 低级钩子（`WH_MOUSE_LL` + `WH_KEYBOARD_LL`，装在 Qt 主线程上），回调只发队列信号、绝不在钩子里翻页；任何退出路径（老板键、关窗、退出、异常）都先卸钩，钩子泄漏的症状是全系统滚轮发卡。
- **已知取舍**：全局热键不拦截按键，进入偷瞄的那一下 Ctrl+E 也会到达焦点应用（和老板键 ctrl+d 在浏览器里顺手加书签同理）；键可换。

## 🛡️ 安全文档模式（Ctrl+Alt+D，本机增补，非上游功能）

- **干什么用**：有时候这个界面被同事瞟到了，你得顺嘴说明屏幕上是什么。按一下 `Ctrl+Alt+D`（可在设置里改 `安全文档热键`），书页**立刻换成一份预置的工作文档**（默认是"服务端接口测试周报"体例：进展 / 风险 / 计划 / 指标 / 结论），看着就是一份普通工作汇报；再按一次换回书，**回到原来那一页**（精确到字）。
- **为什么默认用 Ctrl+Alt+D 而不是 Ctrl+Shift+D**：全局热键**不拦截按键**，那一下会同时落到焦点应用上——`Ctrl+Shift+D` 在 VSCode/PyCharm 是"运行与调试"（弹出一整个面板）、在 Chrome 是"收藏所有标签页"，恰恰在最不该出状况的时候更显眼；`Ctrl+Alt+D` 常见应用里基本没占用。键可以在设置里换。
- **排版和书页一模一样**：安全文档走**同一条渲染管线**，字体 / 字号 / 行距 / 段间距 / 页边距 / 首行缩进 / 颜色 / 透明度全部沿用当前设置，**窗口位置和大小也不动**（角标、防截屏照旧）——从排版上看不出刚刚切换过。
- **预置自己的文档**：设置里「安全文档文件」可指定本机一份 `TXT / MD / EPUB`（复用现有解析）；`safe_doc_path` 留空就用内置那份。**文件读不出来（路径失效/损坏/空文件）自动回落内置版**，任何情况下都不会露出书页，也不会空屏。
- **绝不露馅**：进入时**藏起全部划线高亮**（那几条彩色横条比书页本身还显眼）；安全文档模式下划线 / 书签全禁用（拖选可以选、可以复制，但不会划线、不会弹面板），`Ctrl+L`（目录/书签/划线）和导出**直接不响应**；右键菜单只剩中性项（复制选中文字 / 设置 / 退出），不会出现"打开本地书籍""导出划线笔记"这类字眼。
- **绝不写阅读状态**：模式内翻页**不写** `last_local_pos`、不写 `annotations.json`、不覆盖 `last_local_file`；退出后原书原偏移恢复（书正文是内存里的引用，不重读文件、不卡顿）。
- **来回切，视线和进度都原样**：进出安全文档存/取的不只是"本页页首"，还有**页内滚到哪一行**（`local_top_offset`）——只存页首的话，从安全文档回来会掉回本页最上面，看着就是"进度丢了、往上翻了一截"。同时这一路**绝不写阅读进度**（安全文档模式下 `local_start_index` 是那份假文档的坐标，把 0 或它的偏移写进 `last_local_pos` 等于把读到哪儿整段清掉）；关窗和「退出」这两条路也一并堵上了（以前在安全文档里退出，存的是假文档的第 0 字）。实测修前：翻到 27137、页内滚到 27209，进一次安全文档 `last_local_pos` 就变成 72，在安全文档里按一次老板键唤出又变成 0；修后两次都稳定停在 27137，切回来视口顶仍是 27209。
- **其它模式配合**：老板键（隐藏）在安全文档下照常可用，从隐藏里唤出来**仍停在安全文档**（不会在人家眼前弹回书页）；偷瞄 `Ctrl+E` 也能用，进入时先把真书放回来（cd → ce 滚的是书），**退出偷瞄直接隐藏**、不会退回安全文档。托盘图标提示会写明当前处于安全文档模式（只有你悬停才看得到），**屏幕上不留任何标记**。
- **切换时强制重刷样式**：顺带根治"文字停在透明态"（幽灵模式残留）那种看不见字的状态。
- **配置项**：`safe_key`（默认 `ctrl+shift+d`）、`safe_doc_path`（默认空 = 内置）。

## 🃏 隐形背诵模式（Ctrl+Alt+A，Anki 卡片，本机增补，非上游功能）

- **干什么用**：在工位上背 Anki，但屏幕上**看着像在读文档/周报**——卡片借这本书的排版显示（字体 / 字号 / 行距 / 段间距 / 页边距 / 颜色 / 透明度全部沿用当前设置），窗口位置大小不动。按一下 `Ctrl+Alt+A`（可在设置里改 `背诵热键`）进，再按一次退；**退出后书回到原来那一页，阅读进度一个字节都不变**。
- **键盘**：`空格` / `回车` 翻面 → `1` `2` `3` `4` 评分（就是 Anki 给的按钮顺序，学习步/FSRS 下可能只有 2 个）→ 自动翻到下一张。`R` 重放这一面的音频，`U` 撤销（Anki 的**全局**撤销栈，不只是撤销上一次评分），`Esc` 收起卡片。不想用键盘也行：**鼠标点一下卡片就翻面**，右键菜单里有「翻面 / 1-4 / 重放音频 / 撤销 / 收起卡片」，也可以直接点**页脚上的按钮**。
- **页脚那一行就是"学习计划 + 会变成什么"**：左边是 `新 20 · 学 4 · 复 159　今日已 12　本次 3`（计数一律取 Anki 口径，含每日上限），右边是四个按钮，每个都写着**按下去这张卡会变成什么**——`1 重来 <10 分`、`2 困难 <15 分`、`3 良好 3 天`、`4 容易 7 天`，间隔是 Anki 自己给的 `nextReviews`。**翻面前按钮是灰的**（没看答案不让评分，和 Anki 一致），翻面后亮起来；这张卡只有 2 个按钮时，另外两个直接收掉。安全文档盖上来时整条页脚连同按钮一起消失——周报底下挂一排评分按钮，一眼就露馅。
- **翻面之后按空格不会评分**：Anki 里空格是"良好"，误按一下就把这张卡的排程改了；要评分就明确按数字。评分失败（比如这张卡只有 2 个按钮而按了 4）**只会提示**，绝不假装前进。
- **Anki 忙的时候（同步 / 媒体检查 / 导入）**：退避 2 秒自动重试最多 5 次，状态会讲清楚；**绝不把你的评分悄悄吞掉**。人要是跑去 Anki 自己窗口答题了，这边每 2.5 秒对一次账，评分前也先对一次——不一致就换成 Anki 当前那张，这一下不评分。
- **吞键范围只有 9 个**（`空格/回车/1-4/U/R/Esc`），而且**只在"背诵中 + 窗口可见 + 没最小化 + 没被安全文档盖住"时**才吞：
  - `Ctrl+D` 把窗口收起来 → 一个键都不吞，正常打字不受影响（再按 `Ctrl+D` 回来还是同一张卡）；
  - 设置里关掉「吞掉空格/回车」→ 空格回车还给系统，翻面改用鼠标点一下，评分键仍归卡片；
  - 老板键看门狗每 90 秒的例行重挂**碰不到**这套吞键（钩子和 keyboard 库那套是独立的两个）。
- **和另两个模式怎么配合**：
  | 你在哪 | 按什么 | 结果 |
  | --- | --- | --- |
  | 背诵中 | `Ctrl+D` | 窗口收起，**仍在背诵、还是同一张卡**；收起期间不吞键（再按一次回来还是那张卡） |
  | 背诵中 | `Ctrl+Alt+D` | 换成安全文档（卡片先收着，背诵会话不丢）；再按一次**回到同一张卡** |
  | 背诵中 | `Ctrl+E` | 先退出背诵（书页回来）再偷瞄——偷瞄的**永远是书**，不会偷瞄卡片 |
  | 安全文档中 | `Ctrl+Alt+A` | 安全文档先退掉，再进背诵 |
  | 背诵中 | 关窗口（X） | 整套收起：退出背诵 + 退出安全文档，回到书页 |
- **卡不卡**：AnkiConnect 的每个 `gui*` 动作**固定要 ~60ms**（它必须把请求丢回 Anki 自己的主线程执行）。所以所有 Anki 调用都跑在一条**后台线程**上（串行，保证评分顺序）：进背诵按下就返回（实测 22ms，那一串连 Anki/开牌组/取卡/取计数要 ~700ms 全在后台）、对账每 2.5 秒一次但主线程只花 0.1ms、翻面和评分同样立刻响应。对账带**去重**：Anki 忙的时候同一种查询不会堆成一条队。媒体目录只在进牌组时取一次并缓存（原来每换一张卡都要连一次 Anki）。
- **两个键的分工**（按你的建议改的）：
  - **`Ctrl+D`（老板键）只在"你正在看这个窗口"时生效**：窗口是前台窗口，**或者**鼠标正停在窗口上——两种都说明你在看它。这样浏览器里按 `Ctrl+D` 是正常收藏、编辑器里是复制整行，不会被书窗抢走；而且这个键**不吞**，别人该干嘛干嘛。窗口已经藏起来时不套这一条（那时按它就是"再叫出来"，托盘单击也一样）。
  - **`Ctrl+E`（偷瞄）是全局的，但一个键都不漏给别的软件**：注册时带 suppress，这个组合键从此只属于这里——不会出现"我按了个快捷键"被旁边人看见的破绽。
- **数据边界（重要）**：只走 AnkiConnect HTTP 接口，**绝不读写 `collection.anki2`**——Anki 是唯一真相源，评分、撤销、计时、音频全交给 Anki 自己的 `gui*` 动作，这边一个字节都不改它的库。
- **"藏起来"≠"隐身"**：进背诵时会把 Anki 自己的窗口藏起来（`SW_HIDE`，它不会出现在 Alt+Tab 和任务栏缩略图里），但它**不激活、也不关闭**；实测窗口藏起来之后 GUI 接口照常工作。代价是：别把 Anki 窗口和这个窗口摆在同一块屏幕上——藏起来只是不在眼前，不是不在系统里。退出背诵时 Anki 会回到原处（**不激活**，不会突然跳到屏幕最前面）。
- **配置项**：`anki_key`（默认 `ctrl+alt+a`）、`anki_deck`（牌组名，子牌组自动包含；留空时第一次按热键会打开设置让你挑）、`anki_swallow_keys`（默认开）、`anki_conceal`（默认开）、`anki_api_key`（AnkiConnect 设了 apiKey 才要填）。
- **首次准备**：Anki 里装 AnkiConnect 插件（代码 `2055492159`），Anki 保持运行；设置 → 隐形背诵 → 点「列出牌组…」从正在运行的 Anki 里挑一个（带今日待复习张数）。Anki 没开/没装插件时会**照实说**，不会假装"你没有牌组"。
- **已知边界（先把话说清楚）**：
  - 只做**基础功能**：渲染卡片正反面、翻面、评分、撤销、音频、计数、对账。**不做**：编辑卡片、浏览卡片、统计图表、牌组管理、学习步自定义。
  - 卡片 HTML 会先剥掉整块 `<style>` 和内联字号（否则"字号设置"对卡片时灵时不灵），模板 CSS 只保留颜色/居中/表格这类（去掉字号字体定位 flex/grid）——`QTextEdit` 不是浏览器，`{{tts:}}`、JS、复杂布局不会按 Anki 的样子渲染；`[sound:]` 从显示文本里拿掉，播放交给 Anki。
  - 卡片里的**图片**能显示（按 Anki 的 media 目录解析），但本机媒体库目前没有图片；音频不在这边播放。
  - 音频只在**翻面时自动放这一面**，或按 `R`——不跟 Anki 里"正面也自动播"的设置同步。
  - 计数（待复习 / 今日已复习）一律取 **Anki 的口径**（含每日上限），不在这边现算。

## 🔧 稳定性（本机增补，非上游功能）

- **进度不再跳位**：翻页即存档（本来就有）。真正的坑是恢复进度后，"已恢复进度: xxx.epub" 这条状态消息会把整屏正文覆盖掉，下一次翻页的几何测量把**消息长度当成页宽**，落点从此每次都固定偏移同样多的字——表现为"总是跳到某个特定位置"。现已改为：恢复提示只进日志不上屏，且翻页前核对控件内容，对不上就先重渲再测。
- **重排不跳回（改窗口大小 / 改字号都算）**：重绘原来是"从本页页首重铺"（`local_start_index`），所以用滚轮滚到页中之后，**拖一下右下角改窗口大小**、或在设置里**动一下字号**，视线就被甩回本页最上面——看着就是"阅读记录老是跳回"（若这时翻页，存档还会把甩回去的位置记下来）。现在改成**按锚点重排**：重排前先记下"视口顶那一行第一个字"（`current_top_offset()`），重排后把它当成新页首重铺（`repage_to()`），视线落点一字不差，`last_local_pos` 也同步跟到这一行——重启恢复的就是你正在看的那一行。`apply_style()` 里那条重绘同样按锚点走，所以**改字号 / 行距 / 页边距的实时预览也不会跳**。锚点本身有两道安全阀（`displayed_is_local_page()`）：正文区里现在这屏必须真的等于 `local_full_text[local_start_index:]`（比对前 24 字），**并且**不在安全文档模式，才允许拿几何位置当锚点、才允许写 `last_local_pos`——进出安全文档、切网络书的中间态里正文区和 `local_*` 分属两份内容，此时算出来的锚点是另一份文档的坐标，拿它当页首会把进度改成几十个字（见上一节实测）。顺手把 ncx 目录解析的一个老毛病修了：`navPoint` 原来用 `.iter()` 找 `content`，会串到子节点的 href 上（父章节被指到子章节的锚点），现在只看直接子节点。
- **进度跟着眼睛走（页内滚轮 / 偷瞄滚轮也算）**：本地阅读有两种滚动——翻页会推进 `local_start_index`（页首），而**页内滚轮和偷瞄滚轮只动视口**，页首原地不动，要滚满 5000 字缓冲区才更新一次。原来存档只认页首，于是你在偷瞄里滚了一屏又一屏，存档还停在缓冲区起点：实测人已经在 31819 划线，存档还停在 29161，**差 2700 字**，重启/重新打开就"上翻"回那一行（这正是"阅读进度定位奇怪"的真身）。现在滚动条一动就记一次（`record_view_position`，记的是视口顶那一行），攒 1.2 秒再落盘；老板键收起、关窗、退出也都记"正在看的那一行"而不是本页页首。安全文档模式下不记（那份假文档的坐标不是书的进度）。实测：偷瞄滚 8 格后存档 27011 = 视口顶，重启后第一行字一模一样。
- **锁屏解锁后热键自愈**：锁屏（Win+L）那一刻输入进了 Winlogon 的安全桌面，低级钩子收不到 KEY_UP，于是 Win 就永远留在 keyboard 库的"当前按下键"表里；而热键匹配用的是这张表的排序元组（库内部 `tuple(sorted(_pressed_events))` 去查分发表），多一个 Win 就永远匹配不上 `ctrl+d` / `ctrl+e` / `ctrl+alt+d`——于是老板键、偷瞄键、安全文档键**一起**失灵，只剩托盘能用；而线程活着、`listening` 仍是 True，旧看门狗光看状态什么也查不出来。实测：往 `_pressed_events` 里塞一个 91（Win），ctrl+d 立刻哑；清掉后立刻恢复。现在解锁/登录时窗口会收到 `WM_WTSSESSION_CHANGE` 并主动重挂一整套（连带清掉卡住的按键），看门狗还每两拍（约 90 秒）无条件重挂一次兜底（低级钩子被系统静默摘掉时，状态是查不出来的）。看门狗另外多查一条：真正派发事件的 `processing_thread` 被回调异常打死时，线程和状态全都"正常"、热键却全不响——现在会被发现并重新拉起；三个热键回调也各自兜了 try，不再可能把分发线程带走。
- **老板键自愈**：keyboard 库的全局监听线程偶尔会静默死亡（锁屏、睡眠、钩子被系统强拆），每 45 秒看门狗检查一次，线程死了自动重新注册。
- **事件日志**：main.py 旁边的 `stealthreader.log` 记录老板键触发、显示/隐藏、热键注册失败、恢复进度等关键事件——再遇到"偶尔失灵"，看日志就知道是消息丢了还是窗口没醒。
- **单实例**：双开会两个进程同时响应老板键（看起来像唤醒不了），还会互相覆盖 config 里的进度。第二个进程启动时会被命名互斥体挡下并提示。

## ✍️ 划线高亮与书签（本机增补，非上游功能）

- **划线要先确认**：鼠标在正文里拖选 ≥2 个字，松手会**浮出小面板**——面板本身就是确认这一步。点某个色点 = 划成那个颜色；点「划线」= 用上次的颜色；点「想法」= 划线并写笔记；点「复制」= 只复制不划线。
- **滚动、点别处、敲键盘、Esc 都算"不确认"**：不会划上，而且滚轮照常翻页（不会为了确认挡住阅读）。手滑多带一下不会被误划成高亮。
- **改一条划线**：单击（或右键）已有高亮 → 同一块面板：最左边那个按钮从「划线」变成「取消划线」——**同一个位置、同一支笔，只靠图标状态区分**（没划线是灰笔+虚线下划线，已划线是亮笔+该颜色的实线）；接着是 **5 个色点**直接改色（当前色带白圈）、「编辑想法」、「复制」。带笔记的划线会多一条**虚线下划线**当标记，鼠标悬停显示笔记内容；取消划线要**二次确认**。
- **不会划重**：同一段文字反复确认只留一条（改色而不是叠一条）；确认过或取消过的划选都会立刻清掉，点它不会再冒出新的一条。
- **收藏本页**：`Ctrl+B`，同一个位置再按一次即取消；提示用浮动气泡，**绝不往正文里写消息**（写正文会毁掉翻页的几何测量，见下面「进度跳位」）。
- **目录 / 书签 / 划线三合一**：`Ctrl+L` 或窗口右键菜单打开，三个标签页，**双击跳转、右键删除**，底部一键 **导出 Markdown**——按章节分组，划线原文用引用块，笔记跟在后面，存到书旁边 `<书名>.划线笔记.md`。
- **面板换新时不会互相清掉**：旧面板隐藏时也会发一次"取消"（Qt 的 `hideEvent`），而这个事件是**延迟送达**的——等它到的时候 `self.action_panel` 往往已经换成刚划出来的新面板了，于是新选区被当成"点别处取消"清掉（表现就是"划线时好时不好"，实测三次里错两次）。现在取消回调只认**发信号的那个面板实例**（`on_panel_cancelled(panel)` + 身份比对），旧面板的迟到事件直接忽略（实测连续 10 次拖选全部拿到待确认选区）。
- **外观**：面板和所有右键菜单都是**扁平**的深色圆角卡片——没有投影和立体感，只有 1px 细边框、悬停高亮和细分隔线，不再是系统原生那套灰白边框。
- **位置为什么不漂**：划线存的是**全文字符偏移**，而本地正文就是全文的一段纯切片，所以翻页、改字号、改窗口大小、重启之后落点都精确到字。高亮用 `ExtraSelection` 渲染，**不改正文一个字**；书文件被换掉时按原文片段在 ±3000 字内自动找回，实在找不回的标为「已失效」留在列表里而不是偷偷删掉。
- **移动窗口改了**：正文区现在让给划选，所以移动窗口改成 **中键拖动**，或 **Alt+左键拖动**（触控板没有中键也能用）。
- **隐身细节**：幽灵模式移开鼠标时正文变透明，划线会**一起隐藏**，不会出现「透明窗口上浮着几条彩色带子」。偷瞄模式下正文**照常可用**：左键不退出偷瞄，划选、点划线、翻页都照旧（已划的线在偷瞄模式下也照常可见）。
- **数据文件**：`annotations.json`（和 `main.py` 同目录，已在 `.gitignore`）。备份或换机器就拷这一个文件；一本书记一份，键是书籍绝对路径。
