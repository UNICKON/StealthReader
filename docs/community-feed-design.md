# 社区统一流（Community Feed）设计

> 目标：把知乎 / V2EX / NGA / linux.do / IT之家 / Chiphell / 微博 / 小红书的**列表、正文、评论**
> 统一成一套自己的界面（Reddit 那种），落在阅读器窗口里当一个新页面；微信读书接进现有"书"那一套。

## 1. 真人定的五条（原话，不再改动）

| 问题 | 选择 |
|---|---|
| 点进帖子的正文样式 | "全用我们的排版（同 Reddit）" |
| 评论 | "要，树状可折叠" |
| 首页结构 | "混流为主，可单独筛来源" |
| 图片 | "原样显示" |
| 微信读书归位 | "接进现有'书'那一套" |

范围上还确认过两件事：**不做视频**（B 站/抖音）和**不做音频**（小宇宙/网易云/QQ 音乐）——
"不用那些"。

## 2. 数据模型（全程序唯一一份）

所有来源差异都在适配器里消化，界面层只认这几个字段——**加一个来源 = 加一个适配器**。

```
Post    : source, channel, id, title, author, created, score, n_comments,
          cover_url, excerpt, url, body[Block], tags[]
Comment : id, author, created, score, depth, body[Block], replies[Comment]
Block   : {kind: p|h|quote|code|img|list, text, url, lang}     # 渲染成 HTML
```

适配器接口（每个来源实现同一组）：

```
list(channel, cursor)  -> [Post]           # 列表：免登录源可以不要 cursor
detail(post)           -> Post             # 正文块
comments(post, cursor) -> [Comment]        # 树状评论（拍平后按 parent 重建）
```

各站的"动作"也统一：知乎"赞同"、V2EX"感谢"、微博"转发/点赞"、小红书"赞藏"在界面上
一律是**打开原帖**（第一轮只读，见 §5）。

## 3. 界面与交互

- **首页 = 混流卡片**：来源徽标 + 标题 + 摘要 + 作者/时间/热度/评论数 + 封面。
  默认所有来源按时间/热度混在一条流里；顶部一列来源可点（"全部"+ 各来源），筛选只改列表。
- **帖子详情 = 我们的排版**：正文（字号/行距/页边距跟当前阅读设置走）+ 下面接**树状评论**
  （一层一根竖线、可折叠，见 A.1 第 4 条）。
- **图片**：原样显示；另外给一个**"低调显示"开关**（我补的第二道保险，默认关）：
  无图 + 灰阶 + 紧凑，工位上比老板键更不扎眼。
- **滚动而非翻页**：社区流是无限下拉（按需加载下一页），**不套书那套"切 5000 字缓冲区"**
  的逻辑——那套是给纯文本准备的。

键位（沿用现有分层：模式键全局、页面键窗口内）：

| 键 | 作用 |
|---|---|
| `Ctrl+Alt+F` | 进/出社区页（待确认不与系统冲突） |
| `↑` `↓` / `J` `K` | 在流里移动选中 |
| `Enter` | 进详情 |
| `Backspace` / `Esc` | 返回上一层（详情 → 流） |
| `R` | 刷新当前流 |
| `[` `]` | 上一个/下一个来源筛选 |
| `Z` | 折叠/展开评论节点 |
| `O` | 用系统浏览器打开原帖 |

鼠标（A.1 加）：单击选中一条；**再点同一条**进详情（列表）/折叠（评论）；双击同效。
划选文字仍是复制（走原来的划选路径，两者不冲突）。

## 4. 接进现有程序（复用，不重写）

- **渲染**：沿用 `text_edit`（`QTextEdit` + HTML）。图片直接用现有那套
  `QTextDocument` + baseUrl 取本地文件的机制（Anki 卡片已经在用，见 main.py 第 747 行）。
  不自绘卡片控件——省一整层 UI 代码，而且字号/透明度/页边距/老板键全都自动继承。
- **取数**：沿用 `requests` + 后台线程 + Qt 信号（`ChapterLoader` / `update_text_signal`
  那套）。**所有网络都在线程里**，UI 线程一个 `requests` 都不发。
- **可见层不变**：社区页与卡片页、安全文档页并列，是**内容层**的第三个页面。老板键、偷瞄、
  防截屏、字号、透明度、关闭恢复全部自动生效——分层不动。
- **缓存**：`cache/feed/<source>/<id>.json` + `cache/feed/img/`，带 TTL。刷新失败就显示缓存
  内容 + 顶上一行提示，绝不留白屏。
- **超时与礼貌**：单请求 8 秒超时；同一来源并发 1；翻页间隔 ≥300ms；不做定时后台轮询
  （只在用户按下刷新或进页面时取数），避免无谓流量和风控。

## 5. Cookie 与安全（已定，讲清楚理由）

- **不写进 `config.json`**（那是明文、还会被同步/备份）。单独 `feed_auth.json`，值用 Windows
  DPAPI（`CryptProtectData`，绑定当前用户）加密；设置页只显示"已配置 / 未配置"，不回显。
- **风险要说在前面**：微博、小红书、知乎带 Cookie 的接口有风控，可能触发验证码甚至封号。
  所以每个来源**独立开关、默认关**，失败只降级不重试轰炸。
- **第一轮只读**：不发帖、不点赞、不转发（写操作风险最高、收益最低）。要参与就用 `O`
  打开原帖。这条是我的决定，不是真人要求的。

## 7. 批次计划（每批独立可验收、可单独提交）

- **A 骨架（离线，不碰网络）**：数据模型 + 混流页 + 详情页 + 评论树 + 图片本地渲染 +
  键位 + 与可见层对齐。测试用**本地 JSON 夹具**驱动。→ **已完成**，见下面「A 轮实现笔记」。
- **B 第一批真源（免登录）**：IT之家 + V2EX + linux.do + 知乎热榜。→ **已完成**，
  见下面「B 轮实现笔记」（知乎热榜换了移动端入口后免登录可用，只有正文/评论留在 C）。
- **C 知乎正文与评论**（Cookie；入口已经探明是 `www.zhihu.com/api/v3` 与 App 签名）。
  **前置已做**：凭据管线 + 自检工具（见 C/D 轮笔记），代码会在配了 Cookie 时真去试正文，
  并把结果（成功 / 401 / 403）直接写在详情页上——真正的解析等一次真 Cookie 的响应。
- **D NGA + Chiphell**（论坛 HTML/接口解析）。**NGA 已实现**（默认关，`__output=8` 约定 + 要 Cookie），
  **Chiphell 仍然过不去**。免登录的探测结论：NGA 连 `__output=8` 都返 403 `1:未登录`
  （GBK JSON），首页直接写游客不能访问；Chiphell 对 `/`、`/portal.php`、
  `forum.php?mod=guide&view=hot`、`forum.php?mod=rss&fid=36` 以及移动端变体
  **一律返非标准 HTTP 567 的防爬占位页**。
- **E 微博 + 小红书**（单独开关 + 降级路径）。**微博热搜已做**（免登录，`weibo.com/ajax/side/hotSearch`，
  52 条，默认关、单独开关）；微博正文/评论和**小红书**都要 Cookie（小红书免登录 `/explore` 只是
  36 KB 的空壳 SPA、`api/sns/web/v1/homefeed` 返 500 `create invoker failed`），留在凭据管线之后。
- **F 微信读书接进"书"**：书架 → 章节 → 喂进现有本地书管线（进度、划线、翻页全是现成的）。
  **不做"书单/榜单"那一层**：探测时发现 `weread.qq.com/web/category/rank?type=1` 把 7 个榜单
  （总榜 / 小说榜 / 热搜榜 / 神作榜…）连同书名、作者、封面、简介、推荐值一起内嵌在页面 HTML 的
  `window.__INITIAL_STATE__` 里，**免登录就能拿到**；试做了一版之后**用户明确否掉了
  （"不用这个，榜单没用"），代码已撤**。F 的正题依然只等 Cookie：不打 Cookie 时
  `weread.qq.com/web/shelf/sync` 返 `{"errCode":-2010,"errMsg":"用户不存在"}`，就是"没登录"。

### A 轮实现笔记（写代码时踩到的，B 轮起直接沿用）

- 代码分两块：`feed.py`（纯标准库：模型 / 来源适配器 / 状态机 / HTML 渲染，**不 import Qt、
  不碰网络**）+ `main.py` 里的界面层（取数线程、渲染落盘、键位、页脚）。
  夹具在 `feed_demo/`（`posts.json` + `img/`），`DemoSource` 像真源一样分页、可筛栏目。
- 社区页是**第三个内容页**（书 / 卡片 / 社区互斥）：进页面拍书快照，退出用
  `restore_book_state(snap, write_progress=False)` 原位还原——社区页上的坐标不是书的位置，
  一个字节的阅读进度都不许写；`_book_veiled()` 把 `feed_mode` 一起算进去。
- 页脚**复用背诵那一条**（`update_review_bar` / `fill_review_bar`）：只给状态
  （来源 · 栏目 · 第几条 · 评论多少 · 折了几处），没有按钮、没有键位提示——真人给页脚定的
  规矩原样适用于这里。
- **书页那套逻辑会越权改社区页，五个口子都得在源头堵**（探针一个个逼出来的）：
  `render_local_page`（把 HTML 页换成书的 5000 字缓冲区）、`scroll_page`（翻页顺带改
  `local_start_pos`）、`repage_after_resize`（缩放后重排成书页）、`apply_highlight_selections`
  （书页划线逻辑会清掉社区页的选中高亮）、以及滚轮与偷瞄滚轮（本地书会走"缓冲区滚动"，
  滚到边沿就翻页）。
- **"当前选中哪一条"只能由 extra selection 表示**：一开始把 `▸` 标记和亮色写进 HTML，
  结果光标一动标记就指向过期的那条（高亮永远落不上）。HTML 与选中状态彻底解耦，
  上下移动也就不必重排整篇文档。
- 定位选中项的文本必须和渲染**共用一份拼装**（`feed._comment_header`）。顺带一个坑：
  Qt 的 HTML 解析会把 `　`(U+3000) 折成半角空格，用全角空格拼出来的定位文本在文档里
  根本找不到；列表里的缩进也同理，改成 `margin-left` 而不是前导全角空格。
- 验收：68 项探针（纯逻辑 + 界面两层），跑的时候把 `requests.get/post` 换成抛异常——
  离线这轮**一次网络请求都不许发**；另外回归了老板键、偷瞄、缩放、改字号、退出回书。

### A.1 手感修正（真人看过 A 轮后提的四条）

真人原话四条：**「要支持鼠标点选」「字体颜色导致看不清」「排版不像 reddit」「我们是透明的」**。

1. **鼠标点选**：单击选中一条，**再点同一条**就进去（列表）/折叠（评论），双击同样有效
   （双击的 press→release→dblclick→release 序列走同一条路）。实现不用锚点：`feed.item_needles`
   给出"每条一段定位文本"，界面层**顺序查找**把它们落成块号，鼠标点到的块号就近映射回某一条；
   选中状态仍然只由 extra selection 表示，所以点选和键选共用同一条高亮路径。划选文字照旧是复制。
   *顺序*查找是要点：两条同名作者、同一时间、同一赞数的评论表头一模一样，全文 find 只会命中
   最早那条——高亮永远粘在它上面（探针专门造了这种重复表头来盯）。
2. **颜色**（"看不清"的根因有两个，都在这一轮修掉）：
   - `theme_from_config` 原来只认 `#rrggbb`，而阅读器默认写的是 `rgba(200, 200, 200, 255)`——
     解析静默失败后回落到硬编码灰，于是"跟着阅读设置走"是假的。现在 `#rgb / #rrggbb / rgb() /
     rgba()` 全认，**透明度也原样保留**。
   - 弱化原来是 RGB 乘系数：`216 * 0.45 = 97`，压在透明/半透明窗口上就是看不见的深灰。
     改成**只在亮度（HLS 的 L）上朝中等灰推**：同样的"弱化"是 216 → 176，仍然清楚。
     强调反向推离中等灰。不管正文是深色还是浅色，两个方向都不塌。
3. **透明窗口**：颜色不能靠 config 猜。**取"正文此刻实际在用的颜色"**（正文控件调色板 →
   auto 模式按背景亮度算黑/白 + 透明度 → config 兜底）。auto 模式会把正文换成纯黑或纯白，
   社区页跟着换，才不会出现"浅灰字压在浅色背景上"。
4. **reddit 版式**：标题加粗放大（正文 +3px）→ 来源 · 栏目 · 作者 · 时间（小一号、次要色）→
   摘要 → 图 → `428 赞 · 6 条评论`（**统计行压在卡片底部**，reddit 的招牌）。卡片之间只用留白
   分行（新版 reddit 也是这样，而且真人明确不要底色块）。评论树**一层一根竖线**：用字符画
   `│ ` 重复，不用表格边框也不用 1px 底色格——Qt 的富文本没有"段落左边框"，表格边框颜色不跟
   主题，1px 底色格又正好是真人不要的东西；字符画在任何字体/背景上都一定显示，正文跟着表头
   一起挂竖线，层级一眼看得出来。
5. 顺手修掉两个真 bug（探针逼出来的，都不是这轮新写的代码）：
   - `FeedNav.c_index` 原先按"拍平后的全部评论"取下标，而折叠过滤只作用于显示序列，
     于是**折叠之后往下按一格会停到一条看不见的评论上**（高亮跟着消失）。现在 `c_index`
     一律指 `visible_comments()`，移动也只在看得见的序列里走。
   - `Block.from_dict` / `Comment.from_dict` 只收 dict 和 str，适配器直接给 `Block` / `Comment`
     对象会炸——批次 B 起每个来源都会这么写，先收掉。
- 验收：94 项探针（颜色解析 7、透明窗口可读性 28、版式 16、评论树 7、折叠光标 8、
  鼠标点选/双击/颜色取值 20、重复表头 5、不碰书 5、收尾 1），仍然全程零网络。

### B 轮实现笔记（真源接进来的账）

- **拆成三层**，理由是 A 轮那条"`feed.py` 不 import Qt、不碰网络"不能破：
  `feed.py`（模型 / 状态机 / HTML 渲染，纯标准库，**一个网络调用都没有**）、
  `feed_net.py`（HTTP + 缓存 + 把异常翻成人话）、`feed_sources.py`（每个站一个适配器）。
  探针因此还能离线跑：把来源换成夹具 Http，再把 `requests` 换成抛异常，
  **"一次真网络请求都不发"是可验证的**，不是靠自觉。
- **缓存不是可选项**（`cache/feed/`，已 gitignore）：列表 5 分钟、正文一天、图片永久。
  同一 host 限速 0.25 秒；图片按**内容**嗅探类型（URL 后缀不可信），超过 6MB 不要。
  请求失败时**退回过期缓存**——工位上网络时好时坏，上一次拿到的列表比一片空白有用得多。
- **混流必须并行，而且必须分额**：V2EX 在本机网络连不上（DNS 通、TCP 443 超时），串行取数
  整页要等它一个超时；并行之后等待时间 = 最慢那个站，而且它失败过就**冷却 60 秒**不再去撞。
  分额（`fair_pages`）是因为 IT之家一分钟三条、linux.do 几小时一条：纯按时间排，"混流"
  第一页会被 IT之家整页占满。现在每页每个来源留席位（12 条一页、每个站最多一半），
  被挤下去的条目**顺延到下一页、一条都不丢**（有探针盯这个不变量）。
- **切换来源有两个必须堵的坑**：（1）旧来源的请求还在飞，回来时若不核对来源，就会把上一家的
  帖子套到新来源的名字下面 → 每次取数带 `tag`，对不上直接丢；（2）取数忙着时新请求被
  `feed_busy` 静默丢掉，页面就空着而且没人再补 → 记成 `feed_pending`，这次回来立刻补上。
- **图片只下"看得见的那几张"**：列表一页最多 6 张封面、正文最多 12 张，其余**直接丢掉**而不是
  留个 http 地址（`QTextDocument` 读不了 http，留着就是一排裂图标）。25 张图一次全下会让
  "唤出社区页"等十几秒——这是实测出来的。
- **双击语义修了一处**：`force`（双击）原来落到"只选中"那条分支，等于双击不进详情，
  和 README 写的不一致；现在双击 = 到哪条就动哪条（列表进详情、评论折叠）。
- **各站实测**（2026-10-16，本机网络）：
  - IT之家：热榜 / 最新都通（`m.ithome.com/api/news/newslistpageget`），正文 `newscontent` 通、
    图片能落地。**评论接口试了七个端点全是 404**，所以详情页只显示正文——不编造评论。
    移动端接口挂了会退回 `api/newslist/news`，并且把 `toplist` 和 `newslist` 合起来去重
    （`toplist` 常常只有一条，单靠它这一页就废了）。
  - V2EX：三个公开 JSON（列表 / 详情 / 平铺回复）都写好了，**但本机连不上**，页脚如实报错。
  - linux.do：Discourse 的 `latest.json` 能拿到，但**被 Cloudflare 的盾拦着**，
    要浏览器 Cookie（含 `cf_clearance`，且 UA 必须一致）才过。评论按 `reply_to_post_number`
    还原成真正的树（带环和未挂上父节点的兜底）。排序用**最后回复时间**——
    论坛的热度看的是"还是不是活的"，用建帖时间排会让今天还在聊的老帖沉底。
  - 知乎：**换了个入口就通了**——`www.zhihu.com/api/v3/feed/topstory/hot-lists/total` 401
    （`身份未经过验证`）、`/hot` 与 `/billboard` 403（返 `zh-zse-ck` 让你去算签名），
    但**移动端** `api.zhihu.com/topstory/hot-list` 不要 Cookie：29 条，标题 / 摘要 / 回答数 /
    关注数 / 热度文案 / 真原帖地址都在里面。正文和评论仍然拿不到（`questions/<id>` 403
    「请求参数异常，请升级客户端」，加 `x-api-version`、App UA 都一样；答案列表 403 风控）。
    所以列表这一层接进来了，详情页是**热榜给的真摘要 + 一句"正文要登录"**，评论如实为空，
    整体挪到 C 轮。列表里那条 `target.url` 是 `api.zhihu.com/...` 的接口地址，
    给人点的必须是 `www.zhihu.com/question/<id>`（否则 `O` 打开的是一坨 JSON）。
- **统计数字的单位必须跟着帖子走**：知乎给的是"热度"、IT之家给的是"阅读"、V2EX/Discourse 给的是
  "回复"——同一个数字换个来源含义就变了，写死在渲染层就会把"1326 万"说成"13260000 赞"。
  于是 `score_label` / `comment_label` 存进 `Post`（默认还是"赞 / 条评论"，演示源不受影响），
  上万自动换算成"万 / 亿"。V2EX 的 `replies` 既不是赞也不是热度，所以只当评论数，
  `score` 留 0——不然列表会写成"12 赞 · 12 回复"。移动端接口给 0 的项（IT之家 `hitcount`
  实测全是 0）**就不显示**，不拿 0 冒充数字。
- **栏目列表由来源自己声明**：曾经是渲染层硬拼 `["全部"] + channels`，结果知乎（只有一栏）按 `,`
  会在"全部"和"热榜"之间来回跳、还白清空一次列表——看着像坏了。现在"全部"算不算一栏由 `channels()`
  决定（演示源认它、真实来源不认），切来源/进页面时把栏目落在**来源真的有的第一栏**上，
  页脚因此不会再显示一个不存在的"全部"。
- **视图代次（`feed_gen`）：这一轮最隐蔽的一个坑**。打开详情时如果列表结果还在飞，
  列表回来会把 `nav.reset()` 一执行——**用户刚打开的详情被冲掉，退回列表**（探针里就是这样
  稳定复现的）。只靠来源 `tag` 挡不住，因为这是同一个来源的两次请求。现在每次取数带上"代次"，
  打开详情 / 退回列表 / 切来源 / 切栏目 / 重新拉取都会让代次 +1，代次对不上的结果一律丢掉；
  丢掉时优先执行排队的那次请求（否则人的回车会被吃掉），其次才在需要时补一次列表。
- **验收**（全部零网络 + 一次真机联网）：离线逻辑探针 44 项（知乎映射 / 热度文案 / 详情实话 /
  **断网回落旧缓存** / 单位换算 / 来源登记 / 混流分额 / 转发）、界面集成探针 25 项（真适配器 +
  夹具 Http + `requests` 抛异常，走完整窗：混流三站在第一页、`[` `]` 轮完五个来源、知乎详情、
  `O` 开真原帖、退出不动书的状态）、真机冒烟 27 项（热榜 29 条 0.4 秒、缓存第二次 0.00 秒、
  混流 6 秒并行出 12 条且知乎占 6 条、页脚如实报 V2EX/linux.do 连不上）。

### C/D 轮实现笔记（凭据管线 + NGA，以及"失败的真响应"当夹具）

- **凭据管线**（C/D/E/F 的公共前置）：`feed_auth.json` 里的每个来源拿到
  `cookie` / `user_agent`，`RealSource` 暴露 `has_auth` / `auth_state()` / `auth_note()`。
  界面上"要登录但没配"是**一条状态，不是错误**：页脚写一句"这个来源要 Cookie（feed_auth.json）"，
  免得人对着 NGA 那一片空白猜原因。
- **自检工具 `tests/check_auth.py`**：回答一个具体问题——"我贴的这个 Cookie 到底管不管用"。
  一个站一个站报 HTTP 码、返回体顶层键、一句人话结论（`通了` / `要登录（403 未登录）` /
  `被 Cloudflare 盾拦住` / `非标准 567` / `errCode -2010`）。**带 Cookie 的响应只写 `%TEMP%`**，
  绝不进仓库（里面有用户名、头像地址）。这是"我自己贴 Cookie"这条路上的关键一环：
  没有它，人贴完只能靠"能不能刷出内容"猜。
- **状态码→人话的映射按真响应修了三处**（都是被真响应逼出来的，不是想出来的）：
  1. NGA 免登录的 403 返回体是 **GBK** 的 `{"error":{"0":"1:未登录"}}`——只按 utf-8 解就是乱码，
     关键词永远命不中，于是被含糊地报成"被拒绝（403）"。现在 utf-8 / gbk / `\uXXXX` 转义三种写法都认。
  2. 微博的"要登录"用的是**非标准 432**（空体），原来落到"服务端返回 432"。
  3. Chiphell 的 **567** 是防爬占位页，如实报出来（不假装是 403）。
- **NGA（批次 D 的一半）**：按公开的 `__output=8` 约定写好了列表（`data.__T`）、正文
  （`__T` + `__R`）、正文里 `[quote]` / `[img]` / `[b]` 的最小清理。**没验过的东西不当成验过**：
  解析写成"认不出来就如实说认不出来"，真响应一到手（自检会存到 `%TEMP%`）再收紧。
  默认关闭。Chiphell 那一半仍然过不去：所有路径都是 567 的防爬页，脚本层面没有突破口。
- **知乎**：配了 Cookie 就**真去试一次**正文接口，试到了就显示正文并标明"用的是 Cookie"，
  试不到就把失败原因写在页面上（而不是含糊地说"要登录"）。这条的价值在于：知乎网页接口
  **除了 Cookie 还要前端算 `x-zse-96` 签名**，光有 Cookie 往往不够——这个结论要等真 Cookie
  试一次才能确定，代码现在会把这个结论直接摆在详情页上。
- **"失败"的真响应也是夹具**：`nga_unauth_403.json`、`linuxdo_cf.html`、`chiphell_567.html`、
  `zhihu_unauth_answers.json`、`weread_unauth_shelf.json`——都是没登录/被拦时的**真响应**。
  这类路径最容易被写成"假装成功"，所以更要用真响应盯住。探针里明确分成两类：
  真夹具驱动的（"代码符合那个站"）和标着"（手写形状）"的（只证明"我的解析自洽"）。
- **验收**：`probe_sources.py` **120 项全过**（多了凭据管线、状态码映射、NGA 的收表与标记清理、
  知乎"配了 Cookie 才去试"的三条分支）、`probe_ui.py` **28 项全过**、`probe_live.py` 真机 0 失败；
  `check_auth.py --all` 的基线结论：微博热搜 200、知乎热榜 200 / 正文 403（风控 40362）、
  NGA 403（GBK 未登录）、linux.do CF 403、V2EX 超时、微信读书 `errCode -2010`、Chiphell 567。

### C 轮实现笔记（知乎正文与评论：真 Cookie 一到手就通了）

- **之前那句"光有 Cookie 往往不够"被实测推翻了。** 免登录时答案接口确实 403（风控），
  于是推测"网页接口除了 Cookie 还要前端算 `x-zse-96` 签名"；**贴上浏览器 Cookie 后直接 200**：
  `/api/v4/questions/<qid>/answers?include=data[*].content,excerpt,voteup_count,comment_count&limit=1`
  返回正文 HTML（`data[0].content`），评论接口 `/api/v4/answers/<aid>/comments` 也 200。
  代码、README、探针里那句猜测全部删掉了——**没验证过的推测不许留在给人看的地方**。
- **Cookie 从哪来**：装了 VS Code 摸鱼插件（`ylw.touchfish`）的话，它把各站 Cookie 明文存在
  `%APPDATA%\Code\User\settings.json`。新增 `tests/import_touchfish_cookies.py`：只读插件、
  只写 `feed_auth.json`、**不打印 Cookie 内容**（只报长度和命中标记），加 `--apply` 才落盘。
  这条把"我自己贴 Cookie"从"手抄几 KB"降到一条命令。
- **踩到的真形状**：评论作者嵌了一层——`author.member.name`，第一版按 `author.name` 取，
  拿到的全是空字符串；而且 `author` 整个可能是 `null`（匿名/已注销）。现在两种形状都认，
  认不出来给空字符串（绝不把 `{'role': 'normal'}` 这种给人看的乱码显示出去）。
- **只下一次请求**：详情和评论都要"这条回答"，用 `self._ans` 按问题 id 共用一次请求，
  探针里有一条专门盯它（`len(zs._ans) == 1`）。
- **带 Cookie 的夹具要裁**：知乎正文和评论是别人写的话。`record_fixtures.py` 里
  `_trim_answer` 只留第一段正文、`_trim_comments` 只留前 3 条各前 40 字，头像地址和用户 id
  一概不进仓库。要验的是"字段取对了没有"，不是把别人的文章搬回家。
- **验收**：`probe_sources.py` **126 项全过**（知乎那节从"手写形状"升级成真夹具驱动：
  正文没被吞、作者取的是 `member.name`、赞数与正文都在、匿名不显示乱码、共用一次请求）；
  `probe_live.py` 新增第 4 节"贴了 Cookie 的站"——实测正文 1000 字（0.4 s）、评论拿到、
  图全部落地不外链；`probe_ui.py` 仍 28 项全过。

### D 轮实现笔记（NGA：403 的两种意思，和三个只有真响应才会暴露的坑）

- **先纠正一个我差点写进文档的误判**：`read.php?tid=<第一条>&__output=8` 返 403，
  我一开始判断"正文接口进不去"。**是错的**——返回体里写着
  `5:帖子发布或回复时间超过限制`，也就是"这条帖子太老，NGA 不让看"，
  跟登录、跟权限、跟签名都无关。换成**列表里最新的那条**，正文立刻 200（15.6 KB）。
  教训照旧：**403 不等于没登录**，服务端自己给的原因必须带出来。
  现在 `feed_net` 的 403 分支会先把返回体里那句短原因抠出来（`_short_reason`，
  严格按 utf-8 / gbk 逐个试解，**不能放宽成 `ignore`**——否则 GBK 的中文会被
  "解"成 `5:ӷظʱ䳬` 这种乱码喂给人看，这是实测踩到的），
  `NgaSource.detail` 再把"时间超过限制"翻译成"NGA 不让看这条老帖"。
- **坑一：它的 JSON 里有裸控制字符。** `json.loads` 默认报
  `Invalid control character at line 1 column 924`——要 `strict=False`。
  另外响应自称 `"encode":"gbk"`，按 utf-8 解是乱码。所以 NGA 那条路走
  `get_bytes` + 自己解（`_nga_parse`），不走 `get_json`。
- **坑二：`__T` 有两个含义。** `thread.php` 的 `__T` 是**帖子表**（值是 dict），
  `read.php` 的 `__T` 是**主题元信息**（平字典，值是字符串）。第一版当成一种，
  详情就永远空正文。现在 `_nga_rows` 认不出 dict 就返回空列表，
  探针里两条真夹具分别盯住这两种形状。
- **坑三：列表里混着它自己的错误提示。** `__T` 的第 0 条可能是
  `subject = "帖子发布或回复时间超过限制"`、没有作者也没有时间的那条——照收的话
  **列表第一条就是一句报错**。夹具直接把这条录下来了（`nga_list.json` 的 6 条里有 1 条是它），
  所以这个 bug 是夹具抓出来的，不是我想出来的。现在按"有没有作者和时间"筛掉。
- **顺带两个小坑**：正文里的图是**相对路径**（`[img]./mon_202610/16/xxx.jpg[/img]`），
  要用响应里的 `__GLOBAL._ATTACH_BASE_VIEW`（实测 `img.nga.cn/attachments`）补全才落得到本地；
  回复接口**对其他用户只给 `UID:12345678` 占位串**，不给真昵称——认不出真名就留空，
  页面上宁可不显示作者，也不显示 `UID:67020159` 这种给人看的占位串。
  回复也没有真正的层级（引用写在正文里），按平铺给。
- **默认开还是默认关**：NGA 进了默认列表。理由是"没配 Cookie 时它会照实说'这个来源要 Cookie'"，
  页脚能给人解释，比"藏起来让人找不到"更好回答"为什么没有 NGA"。
  微博仍然不进默认（风控最紧，属于单独开关那一档）。
- **验收**：`probe_sources.py` **143 项全过**（NGA 那节整段换成真夹具驱动：
  列表筛选、`__T` 两种含义、GBK+strict、`lou=0` 取楼主帖、相对路径图落地、
  BBCode 清理、UID 占位名不显示、老帖 403 翻译成人话且不谎称"要登录"）；
  `probe_live.py` 的第 4 节同时验知乎和 NGA（真网络：列表 49 条、正文、评论）。

### E 轮实现笔记（小红书：内容不在接口里，在页面里）

- **它跟别的站不一样的地方**：这里没有可用的数据接口，**内容就是服务端渲染在 HTML 里的**。
  免登录时 `/explore` 是一张 36 KB 的空壳（SPA 骨架，什么都没有）；**贴上浏览器 Cookie 之后
  同一张页面 228 KB**，`window.__INITIAL_STATE__.feed.feeds` 里就是列表（30+ 条），
  每条带 `id` / `xsecToken` / `noteCard`（标题、作者、赞数、封面）；正文在
  `note.noteDetailMap[<id>].note`（`desc` / `imageList` / `tagList` / `interactInfo`）。
  2026-10-16 实测：列表 32 条（4.1 s，封面落 6 张）、正文 180–375 字、正文里不留外链。
- **`xsec_token` 是这个站的门槛**：列表给的每条都带 token，详情地址必须带上它
  （`/explore/<id>?xsec_token=…&xsec_source=pc_feed`），不带就打不开。所以 token 跟着 `O` 的地址一起存，
  丢了就如实说"token 丢了"——这个站的文件不会永远有效，**过期的表现就是状态里没有这条笔记**，
  那种情况也说清楚是过期，不说"没找到"。
- **抠 `__INITIAL_STATE__` 有两个坑，都是实测踩的**：
  1. **非贪婪正则会把状态截断**——对象里第一个 `}<` 出现在**字符串里面**，用 `(\{.*?\})\s*<`
     抠出来的东西少 1.5 KB 而且必然解不开。必须按括号配对扫，还要跳过字符串和转义；
  2. 它是 **JS 字面量**，里面有 `undefined`、`new Map([])`、`new Set([])`（JSON 全不认），
     得先替换掉。探针里专门留了两条**手写形状**盯住这两点（真页面上就是这么发的）。
- **评论这一层：测不到就不做，而且要写在画面上**。评论接口
  `/api/sns/web/v2/comment/page` 实测 **406 `{"code":-1,"success":false}`**（要前端签名，
  `edith.xiaohongshu.com` 和 `www` 两个域名都试了）；页面自带的 `comments.list` 时有时无——
  录夹具时**连看 10 条笔记，一条都没带上**。既然拿不到真夹具，就不留"猜出来的解析"：
  `comments()` 直接返回空，正文末尾挂一句实话（"这里只有正文和图片……按 O 去原页看评论"），
  **不装成"这条没人评论"**。哪天录到一份真带的，再把这一层打开。
- **顺手三个小规矩**：时间字段是**毫秒**（`feed.parse_time` 自己认毫秒，本来就有这行逻辑，
  所以适配器里不用再除一次，第一版多写了一次、被探针的断言逼着删掉）；
  **视频笔记跳过**（`noteCard.type == "video"`：这个窗口不放视频，收下来也只是个壳）；
  免登录空壳页要报"它要登录，把 Cookie 贴到 feed_auth.json"，而不是甩一句"改版了"——
  所以 `list()` 会把状态块那条错误包一层人话再抛。
- **默认开还是默认关**：跟 NGA 同理，进默认列表（没配 Cookie 时页脚照实说"这个来源要 Cookie"）。
  微博仍然不进默认。
- **验收**：`probe_sources.py` **160 项全过**（小红书那节 17 项：真夹具的列表字段/token/视频跳过、
  空壳页报"要登录"、正文 desc 与话题标记、毫秒时间、图片落地、评论如实为空、详情只拉一次、
  token 丢了怎么说，加两条 JS 字面量的手写形状）；`probe_ui.py` 28 项全过；
  `probe_live.py` 第 4 节：知乎 + NGA + 小红书，真网络 0 失败。

## 8. 这轮明确不做

视频、音频、发帖/点赞/转发等写操作、多账号、整站离线下载、自建代理、云同步阅读进度。

## 9. 验收方式

- 每个来源保存**真实响应夹具**，探针离线跑：不联网、不碰真实账号、结果可重复。
  A 轮的夹具是手写的（`feed_demo/posts.json`），B 轮起换成真实响应存下来的夹具。
  **E 轮起探针与夹具都进仓库**（`tests/`），所以"零网络"是可复现、可回归的：
  `probe_sources.py` / `probe_ui.py` 开头就把 `requests` 换成抛异常。
- 网络路径只做一次手动"真实拉取"冒烟；失败必须降级到缓存并给出可见提示。
- 排版、老板键、偷瞄、防截屏沿用现有探针回归（一条都不能退）。

6. "低调显示"开关（无图 + 灰阶 + 紧凑）。
